## 0. 结论

**当前冻结 A2 在已有可验证负载中未显示独立重计算收益；Native LRU 排序与模型成本排序高度重合，
Reuse Proxy 的有效性也缺乏充分支持。因此，现阶段不建议继续将冻结 A2 作为主要工程投入方向。
该判断不是 A2 理论上绝无优化空间的证明。**

本文的作用是把这条判断拆成可核对的结构条件，并明确每条结论的适用范围；
凡超出证据的地方都在文中标注，而不是在结论里含糊带过。

## 1. 冻结目标只依赖一个剖面向量

$$L(S)=\sum_{c:\,S\cap c\neq\varnothing} q_c\bigl(m_c-j_c(S)+1\bigr),
\qquad j_c(S)=\min\{d_c(b):b\in S,\ b\in c\}$$

$L$ 只通过**开启剖面** $\mathbf{j}=(j_c)$ 依赖 $S$。这带来两条受限的引理，
它们的适用条件比初版窄，故逐条写明。

---

## 2. 引理 A —— 链内单调（仅对私有块成立）

### 2.1 陈述

设某条链 $c$ 上**只有私有块**（$|O(b)|=1$），且名额 $k_c$ 已定。把 $S\cap c$ 中任一
深度换成同链更深的未淘汰块，$j_c$ 单调不减，$(m_c-j_c+1)$ 单调不增 ⇒
**在该链的私有块内，最深 $k_c$ 个是最优的**。

> 推论（受限）：对**纯私有块的单链子问题**，链内定价不携带决策信息——
> 它不需要 $q$、不需要几何、不需要预测。

### 2.2 为什么不能推广到共享块

一旦链内有共享块，"链 $c$ 上取几个"**本身就无法独立定义**：
一个物理块同时占据多个链的深度，把它在链 $a$ 上推向更深处，可能同时在链 $b$ 上
推向更浅处。一次淘汰无法对各链独立地做到"最深"，因此
**§2.1 的论证在共享块上不成立**，成本模型的链内结构在此处留下真实自由度。

M1 的 RC1 指出的正是这一点。初版把这条推论写成"链内排序不携带任何决策信息"，
在无共享的语料上成立，在一般情形下过强，此处已限定。

---

## 3. 引理 B —— 均匀 $q$ 下**规范受害集**之间的平坦性

### 3.1 陈述

称 $S$ 为**规范（canonical）受害集**，若它满足：

1. 不淘汰任何共享块；
2. 每条链贡献的是一段**连续的最深后缀**（即满足 §2.1 的形式）。

则各链 $q_c\equiv\bar q$ 时，每条链贡献 $\bar q\,k_c$，总损失
$=\bar q\sum_c k_c=\bar q k$ —— **与名额如何分配无关**。

探针验证（`canonical_flatness`，两链各长 4，$q\equiv0.5$）：

```text
k=1: a 取 0 / b 取 1  → 0.5000      a 取 1 / b 取 0 → 0.5000     flat=True
k=2: 三种分配         → 1.0000                                  flat=True
```

### 3.2 为什么不能说"所有合法受害集损失恒等"

**不成立**，规范集之外可以取到不同的损失。最小反例见 §4。
因此本文只宣称：**在规范集族内**，均匀 $q$ 使选择完全平坦；
**在一般合法集上，损失可以不同**，只是这些差异未必能被更优地利用。

---

## 4. 最小反例：「Native 已最优」≠「所有选择成本相同」

这两件事**不等价**，而 PR #69 初版把前者写成了后者。反例
（`scripts/probes/a2_uniform_q_counterexample.py`）：两条 3 块链，共享块在两条链的深度 2，
$q\equiv0.5$，**无深度反转**（深度 2 的块比深度 3 的块更暖），`need = 1`。

| 受害集 | 成员 | $L$ |
|---|---|---:|
| block 3 | $a@3$ | **0.5000** |
| block 5 | $b@3$ | **0.5000** |
| block 1 | $a@1$ | 1.5000 |
| block 4 | $b@1$ | 1.5000 |
| block 2 | $a@2 + b@2$（共享） | 2.0000 |

```text
distinct loss values: [0.5, 1.5, 2.0]
all legal sets cost the same: False
native picks (3,), L = 0.5000
optimal L = 0.5000
native already optimal: True
```

**读法**：

- **合法集的损失不同**（0.5 / 1.5 / 2.0）—— 共享归属确实打破 §3 的平坦性；
- **但 native 已经在该决策的最优点** —— 差异存在，不等于存在可利用的收益。

这两点必须分开陈述。初版把"平坦"当作所有合法集的性质，导致把
"此处无收益"误写成"此处无从不同"，这是本文最重要的更正。

## 5. 收益的结构条件（问题 1）

在冻结模型下，背离 native 且**降低** proxy loss 需要下列条件之一：

| 来源 | 条件 | 性质 |
|---|---|---|
| **(D) 深度反转** | 同链内更浅的块反而更冷，native 先打浅块 | 使 native 落在非规范集上 |
| **(Q) 链间 $q$ 重排** | 多链 + $\Delta q$ 足够大 | 使规范集之间的最优分配改变 |
| **(S) 共享归属** | 淘汰一个多链共享块，一次抬高多个缺口 | **见 5.2：在本文的枚举空间内总是伴随 (D)** |

### 5.1 (Q) 的形态：单决策 proxy gain

非反转、无共享的规范几何，$need=k$，两链 $q$ 分别为 $q_{\text{cold}}<q_{\text{hot}}$：

| $q_{\text{cold}}$ | $q_{\text{hot}}$ | native | cost-aware | $L$(native) | $L$(aware) | proxy gain |
|---:|---:|---|---|---:|---:|---:|
| 0.50 | 0.50 | (107,106) | (107,106) | 1.0000 | 1.0000 | **0.0000** |
| 0.40 | 0.60 | (107,106) | (103,102) | 1.2000 | 0.8000 | 0.4000 |
| 0.01 | 0.99 | (107,106) | (103,102) | 1.9800 | 0.0200 | 1.9600 |

> **这是 proxy gain，不是 token 收益。** 数值为 $k\,(q_{\text{hot}}-q_{\text{cold}})$
> 只在这个特定几何下成立（无共享、连续最深后缀、$B$ 已约去）。
> 它**不能**作为实际重算 token 的上界或下界，理由见 §5.3。

### 5.2 (S) 与 (D) 在本文的探针中不可分离

共享块只有在 native 会选中它时才可能带来收益；而"共享块位于链的较浅深度、
却比更深的私有块更冷"按定义就是一次 (D)。因此
**本文的共享探针同时包含 (D)**，不能算作独立的共享效应证据。

- 随机探针（$q\equiv0.5$）：308 个出现正 proxy gain 的决策，**全部** `inverted=True`；
- 2×2 分类（`shared × inverted`）中没有出现"有共享、无反转、有收益"的格子；
- **穷举**小几何（2 链、长度 2–4、含一个共享块、块数 ≤ 6、全部非反转排列）：
  **86 个几何，正 proxy gain 的分歧 0 个**。

```text
== shared effect vs inversion effect (uniform q) ==
  shared  inverted   decisions   strictly better   best gain
   False     False         743                 0      0.0000
    True     False          40                 0      0.0000
    True      True         717                 0      0.0000

== exhaustive small non-inverted geometries WITH a shared block ==
  geometries checked: 86
  divergences with a positive proxy gain: 0
```

> 这是**枚举空间的观察**，不是"共享永不独立有用"的定理。它说明的是：
> 在我们能穷举的范围内，共享的收益无法脱离 (D) 出现。

### 5.3 为什么不能把 proxy gain 当作 token 上界

$q_c$ 未校准，$L$ 的单位是**加权块单位**（$B$ 已约去）；而实际
`aggregate_recomputed_tokens` 由 APC 命中/未命中决定，实测存在**部分命中**
（`loss == 16×block_count` 仅成立 159/207），且每块实际重算量跨度 24×。

因此：

- 不能用 $k\Delta q B$ 作为"实际 token 收益"的严格上界或下界；
- 不能用它推断"F4 的 +560 tokens 不可能由 block selection 造成"；
- 可以说的是：**在规范几何下，单决策的 proxy 差异是 $k\Delta q$ 量级**；
  把它换成 token 需要 $B$ 与命中率两个本文未建立的假设。

代理尺度与真实尺度之间的差距本身是本文的结论之一，而不是可用来定罪的工具。

## 6. 等价 / 近似等价的条件（问题 2）

1. **单链窗口 + 全为私有块 + native deepest-first** → 与 (A) 同集（引理 A）。
2. **多链 + 规范集 + $\Delta q=0$ + native deepest-first** → 规范集之间损失相同（引理 B），
   故选择无差别；但**非规范集损失可以不同**（§4），只是 native 已然最优。
3. **`need` = 合法块总数** → 任何规则必须淘汰整个合法集，**构造上不可能分歧**。

补充（受探针范围约束）：在 $q\equiv0.5$、无共享的 4000 个随机决策中，
**无反转 ⇒ 分歧 0**；在含共享的 86 个穷举非反转几何中同样为 0。

> 这**不**等于"一般情形的优化空间为零"。探针只覆盖：均匀 $q$、小型几何、
> 两个至三个链、`need ≤ 3`。非均匀 $q$ 下 §5.1 的 (Q) 确实产生分歧，
> 而真实语料的 $\Delta q$ 分布本文并未测得。

### 6.1 贪婪不是瓶颈

贪婪在单链私有块上精确（引理 A），在 (Q) 重排下也精确（边际成本单调）。
它只在**共享耦合**时次优，实测缺口 0.68%（25/3684，最大 0.70 块），穷举搜索已覆盖。
因此本轮未观测到收益，不能归因于"选择器不够好"，但也不能据此排除结构本身有问题。

### 6.2 探针限制（明确列出）

| 限制 | 影响 |
|---|---|
| 只测均匀 $q$ 的结构族 | (Q) 的触发率未在真实 $\Delta q$ 分布上测过 |
| 几何为合成小规模 | 不覆盖真实链长分布与共享拓扑 |
| proxy loss 而非 token | 真实 token 效应需要 Native 测量 |
| 反转判定基于 `native_rank` vs `depth` | 真实的 rank 语义可能含 tier 等其它分量 |

## 7. Reuse Proxy：可保留的假设与不可推出的结论（问题 3）

### 7.1 机制形式

`retention_deadline_timestamp = ttl_decision_timestamp + ttl_seconds`，
故 deadline 之差可分解为

$$\text{deadline}_c-t=\underbrace{\texttt{ttl}_c}_{\text{TTL 估计}}-\underbrace{(t-t_{0,c})}_{\text{Entry 年龄}}$$

$q_c$ 是这个量的 sigmoid。所以 $q$ 只编码两件事：**TTL 估计的差异**与**Entry 年龄的差异**。

### 7.2 Cold-start **不**意味着各链 $q$ 相同

初版写"cold-start 常数 TTL ⇒ 同一决策内 $q$ 全相同 ⇒ 决策完全平坦"，这是**错的**：
即使 $\texttt{ttl}_c$ 为常数，各链的 `ttl_decision_timestamp` $t_{0,c}$ 可以不同，
deadline 随之不同，$q$ 仍然不同。

正确的说法要弱得多：

> cold-start 只**移除了 TTL 异质性这一条通道**，使 $q$ 的排序退化为
> $t_{0,c}$ 的排序（即 Entry 层年龄），而不是使 $q$ 变为常数。

它仍是一条减弱信号的理由（Entry 年龄在 block 层已由 recency 粗粒度反映），
但**不是**"决策平坦"的证明。F1–F3、F5–F6 全 TIED 的**成因**本文不作断言。

### 7.3 "与 recency 共线"：有证据限制的假设

**可以保留为假设**的证据（H1 bundle，决策内秩相关，口径见 M4 审计 §2.5）：

| 特征 | ρ | 族一致 |
|---|---:|---:|
| `retention_deadline_timestamp` | +0.0585 | 0.667 |
| `elapsed_since_ttl_decision_seconds` | −0.0585 | 0.667 |
| `decision_native_lru_position` | +0.0585 | 0.667 |
| `block_count`（结构项） | 0.5999 | 1.000 |

三者 |ρ| 与族一致度相同、仅符号随单调方向翻转，与"决策内三者近似秩等价"相容。

**必须同时声明的限制**：

- 语料是 **H1**，不是本轮 A2 Native bounded evaluation 的语料；
- 该统计量是**决策内秩归一化后的 pooled 相关**，衡量边际关联，
  **不排除条件相关非零**；
- 它与 M6 `signal_support.jsonl` 的口径不逐位一致（见 M4 审计 §2.5）。

> 因此结论只能写成：**在 H1 语料上，deadline 型信号与 recency 高度重合，
> 且与 runtime loss 的边际相关接近零（−0.0178，n=207）。**
> 这**不足以**断言"$q$ 在当前 A2 Native 决策中提供零独立信息"。
> 要断言后者，需要在 A2 自己的语料上做决策内条件分析，本文未做。

### 7.4 仍可保留的三个较弱观察

1. **链内零信息**（结构性，非统计）：$q_c$ 是链级标量，链内所有私有块共享同一 $q_c$，
   故它对链内排序的贡献恒为 0。这一条不依赖任何语料。
2. **错误代价不对称**：$q$ 判高会主动保护该链、把代价转给别处，
   故 $q$ 的错误不是"无操作"而是"有方向的错误"。这是模型性质，不是实测结论。
3. **proxy 与 token 的对齐缺口**：`loss == 16×block_count` 仅 159/207 成立，每块实际
   重算量跨度 24×，且模型未考虑"该链本来就会被 Continuum 释放"，也按常数 $B$ 计末块。

## 8. 与 A1 的关系：层级假设（未在本轮验证）（问题 4）

### 8.1 结构：两层的决策变量不同

A1 决定 $E(R)$（哪些 Entry 被释放 ⇒ 哪些链**可以**被碰）；
A2 只在 $E(R)$ 内决定淘汰到多深、淘汰哪几个。

### 8.2 "A1 压缩 A2 残差"是假设，不是本轮事实

A1 的评分 $\widehat R_i=q_i[\min(need,N_i)+\lambda(N_i-\min(need,N_i))^{+}]$
与 A2 使用**同一个 $q$ 与同一个后缀逻辑**，因此**可以提出**：
A1 先把低 $q$ 的 Entry 放进 $E(R)$，使 $E(R)$ 内的 $\Delta q$ 收缩，从而压缩 A2 的收益上限。

> **但本轮实验采用的是 A0 Entry Release**，不是 A1。
> 因此"$E(R)$ 内 $\Delta q$ 已被压缩"这一环**没有在本轮被验证**；
> 它是对 A1+A2 联合配置的推论，属于待检验假设。

### 8.3 可对照的观测差异（仅陈述，不作因果）

| 证据 | Entry 层 | Block 层 |
|---|---|---|
| 选择分歧 | Gate 2 语料 13 个场景 | 离线语料 0/87；native 战役 2 个窗口 |
| 观测到的收益 | 有 paired 证据 | 未观测到（0 BETTER / 3 WORSE / 33 TIED） |
| 可移动量级 | Entry 是否释放 ⇒ 整链后缀 | §5.1 的 proxy 尺度，真实 token 效应未测 |

两栏的分歧计数**不能直接相减**：语料、回退率与身份可验证性都不同。

## 9. 建议（均未获授权，仅作提案）

1. **A2 降级为条件门控 opt-in 安全层**：默认返回 native，仅当 (D) 或 (Q) 可判定为真时背离。
   在已有可验证语料上该门控会大量走 native——既不退化，也不假装有收益。
2. **主线回到 Entry 层（A1 / A3）**：那是唯一有 paired 收益证据的层级。
3. **把主指标换成条件触发率 × proxy 幅度，并单列 token 口径**：后者在 33/36 TIED
   与 51.7% 回退下没有检出力；前者至少可离线算完。

若 M1 希望保留 A2，建议的可检验准入命题（**以待裁定**）：

> 在已验证（identity-proved、非回退）决策中，
> (D)/(Q) 的联合触发率 × 单决策 proxy 增益，必须能与可观测的 token 变化方向一致；
> 否则 A2 的期望收益缺乏测量基础。

注意这**不是** token 上界论证——proxy 增益与 token 之间的换算关系尚未建立（§5.3）。
