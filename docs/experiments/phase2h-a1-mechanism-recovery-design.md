# Entry-level Cost-Aware 机制恢复与改进设计建议

**分支**：`design/phase2h-a1-history-rich-recovery`
**阶段**：History-Rich Native Replay 机制恢复研究（算法机制与研究层面）
**边界**：本文只做分析与设计。未修改冻结 A1/A2，未新增 λ/N 语义，未启动 Campaign，未提交 A1+ 实现。
**配套脚本**：`scripts/probes/entry_costaware_audit/history_recovery_analysis.py`（只读，可复现全部数字）

---

## 0. 结论摘要

1. 当前 A1 的失效不是单一原因，而是**四条相互独立的阻塞**，其中只有第一条是 M6 可以靠加历史解决的。
2. **本轮的核心发现：把历史从 Cold-start 换成满足阈值的真实历史，并未改变本负载上这些决策的 q 排序。**
   用真实冻结算法 `ttl.estimate_ttl` 在 **29 个已配对**的 A1 决策（其中 18 个多候选）上重算：
   经验 TTL 中位 **0.347 s**，Δq 中位 **+2.7e-3**（最大 +3.0e-3），
   q 排序改变 **0 / 29**（多候选子集 **0 / 18**），argmin 改变 **0 / 18**。
   这个结论**只适用于本负载与本历史分布**，不能推广为“任何 History-Rich Replay 下都不会改变”（§2.2）。
3. 可证明的那一半是上界：`|Δq| ≤ B/(4τ)`。本负载的 `B` 中位 0.91 s，所以变化被限制在 1.2% 以内。
   **这是一个关于冻结 TTL 规则的性质，不是对 M6 Workload 设计的硬性要求**（§2.3）。
4. 真正缺的是**与 elapsed 独立的、在候选之间有变异的复用信号**。现有数据中结构上满足这个定义的是
   **“该 Entry 被逐出后是否被重新请求”**；但本负载只记录逐出，不记录逐出内容是否被重取，因此不可算（§3.1）。
5. 评分结构在**所有候选都 sufficient** 时高度依赖 q（本数据 18/18 决策均如此）。
   λ **并非完全不起作用**：λ=0 与冻结的 λ=0.5 在 **2 / 18** 个决策上产生不同选择，且两者均在 **g05**（§1.4）。
   这与此前 phase2g 的“2 个改变、均 g05”一致。

## 1. 当前 A1 的主要失效原因及其证据

按"能否由 M6 解决"排序，四条互不替代。

### 1.1 阻塞一：历史机制不可达（M6 可解）

| 事实 | 值 | 来源 |
|---|---|---|
| 每 run 可产生的 server gap | `REQUEST_ARRIVED − PROGRAM_STARTED` = 216 − 36 = **180 / 18 runs = 10 / run** | v10 A1 臂事件计数 |
| 冻结阈值 | **100** | `continuum/config.py` `duration_history_threshold` |
| 因此 TTL 模式 | **恒为 `COLD_START`** | `ttl._select_history` |
| 归档是否记录 gap 样本数 | **否**：`TTL_HISTORY_INPUT_OBSERVED` 只有 eta 与 queue-delay 计数（180/180 全为 0） | 事件 payload |

所以 10 这个数字是**由事件计数推出**的，不是从归档读到的。这一点本身是 M6 的观测缺口（§5.1）。

### 1.2 阻塞二：**把历史换成真实分布后，q 排序在本负载上未改变**（M6 不可解，本轮核心）

做法：把 W1-A 的 443 条真实 gap 注入 `TTLInput`，
调用**冻结实现** `estimate_ttl(..., duration_history_threshold=100)`，得到该 run 会选的 TTL，
再按 `deadline = ttl_decision + ttl` 重算 q。

配对方式（本轮修正）：不按 timestamp，而按 **`event_index` 顺序 + `(program_id, prefix_id)` 身份**配对。
`FORCED_RELEASE_DECISION` 位于 `continuum_pressure`，`COST_AWARE_RELEASE_DECISION` 位于
`continuum_logical_replay`，两者时间戳数值接近但分属不同时钟域，邻近不等于对应。

| 项 | 结果 |
|---|---|
| trace 中的 release 决策 | 29 |
| **按 index + 身份成功配对** | **29 / 29**（0 个拒绝） |
| 其中多候选决策 | 18 |
| 缺失 prefill 的配对 | 0（缺失则**排除**，不代入默认值） |
| 时间算术自检 `max|sigmoid((deadline−t)/τ) − 记录 q|` | **0.000e+00** |
| 历史来源 | W1-A，**443** 条，中位 0.2799 s，p90 0.3638 s |
| 样本数 > 阈值 | 是（443 > 100），**不再是 COLD_START** |
| `next_tool_type` = `observed-agent-gap` 在 W1-A 中的样本 | **0 条** → 模式是 `GLOBAL`，`TOOL_SPECIFIC` 仍不可达 |
| benefit `B = queue_delay·η + prefill_reload` | 0.2254 / **0.9076** / 1.4392（min / 中位 / max） |
| 经验 TTL（真实代码算出） | 中位 **0.3474 s**，范围 0.0157 – 0.3653 |
| 由此产生的 q 变化 | 中位 **+2.727e-3**，最大 **+3.044e-3** |
| 理论上界 `B/(4τ)` | **0.012** |
| **q 排序改变** | **0 / 29**（多候选 **0 / 18**） |
| **argmin 改变** | **0 / 18** |

说明两点：

- `prefill_reload` 取 `FORCED_RELEASE_DECISION` 候选里的**真实记录值**；
  `selection_trace` 里的 `per_unit × new_blocks` 是加权块单位的 `expected_recompute`，不是秒数。
  配对失败或缺失 prefill 的决策一律**排除并记数**，不填默认值。
- 时间算术没有被默认：`elapsed = release_time − deadline` 的有效性由“重算 q 与记录 q 的残差为 0”验证。

结论的范围：**在本负载 + 本历史分布下，这批决策的 q 排序未改变。**
这不等于“任何 History-Rich Replay 中 q 排序都不会改变”（§2.2）。

### 1.3 阻塞三：q 与 elapsed 是同一个量（M6 不可解）

在 47 个带 trace 的候选行上验证：

```text
max |sigmoid((deadline − t)/τ) − 记录 q| = 0.000e+00
Spearman(elapsed, q)                     = −1.000000
```

`COLD_START` 下 `ttl = default_ttl_seconds` 是启动常数（v10 的记录值为 `0.0`），
所以 `deadline = TTL 决策时刻`，`q = sigmoid(−elapsed/τ)`。
**q 不是"较弱的复用信号"，它就是 recency 本身。**

### 1.4 阻塞四：所有候选 sufficient 时，排序高度依赖 q（M6 部分可解）

用**反解记录的分数**恢复 A1 实际使用的 `need`（`need = (expected/q − λN)/(1−λ)`）：18 个决策全部可恢复，
候选间估计值**无不一致**，恢复值 1 – 114，中位 8。

| 项 | 值 |
|---|---|
| 每决策 sufficient 候选数 | **18/18 决策中全部候选均 sufficient** |
| `N_i` max/min 中位 | **1.53** |
| q 决策内跨度中位 | **0.441** |
| λ=0 vs 冻结 λ=0.5 的选择分歧 | **2 / 18**，均在 **g05**（deep 与 moderate 各 1） |
| λ=0.25 vs λ=0.5 的分歧 | **1 / 18**（g05-low-high-deep） |
| λ=1.0 vs λ=0.5 的分歧 | **0 / 18** |

两点必须同时说：

1. 当所有候选都 sufficient 时，`min(need, N_i) = need` 对每个候选相同，
   括号内只剩 `λ(N_i − need)`，而 `N_i` 的离散度只有 1.53×，远小于 q 的跨度。
   因此**排序主要由 q 决定**，这是形式问题，不是调参问题。
2. 但 **λ 并非完全不起作用**：λ=0 把 `N` 项完全去掉后，2 个 g05 决策选出不同答案。
   这与此前 phase2g 的 λ 消融（27 个无关、2 个改变，均在 g05）**一致**，不构成矛盾。

**本轮修正**：早期版本的 λ 遍历按 (0, 0.25, 0.5, 1.0) 顺序执行，而基准只在 `λ==0.5` 时才建立，
导致 λ=0 与 λ=0.25 实际未与基准比较。现已改为先计算全部 λ 的 argmin，再统一与冻结 λ=0.5 比较。

### 1.5 补充：`N_i` 的语义不等同于重算代价，`required_blocks` 也不等于 `need`

单个决策的实例（`g01-short-extreme-deep-a1-repeat-1`）：

| 量 | 值 |
|---|---|
| pressure 事件里的 `required_blocks` | **128** |
| **反解得到的 A1 实际 `need`** | **36** |
| 候选 A `django__django-13569` 的 `new_blocks` | **1620** |
| 候选 B `psf__requests-2931` 的 `new_blocks` | **200** |
| 实际释放的 `newly_eligible` | **200**（即不选 A） |

**两个口径都要区分**：

- `required_blocks`（压力事件记录的）**不是** A1 评分时的 `need`；把前者当后者会算错每一个决策。
  本报告一律用反解值，并已验证 18/18 候选间一致。
- `N_i` = 释放该 Entry 后**新增 eligible** 的块数。它既不是物理逐出的块数，也不是会被重算的块数：
  - 新增 eligible 之后，由 native 压力路径决定哪些真的被逐出（本 run 共 1084 次 `BLOCK_EVICTED`）；
  - 被逐出的块只有在之后被重新请求、且 APC 未命中时，才产生重算。

## 2. 解除 Cold-start 后应当出现的可验证机制变化

### 2.1 应当出现（正向观测）

| # | 可观测变化 | 判据 | 备注 |
|---|---|---|---|
| 1 | 历史样本数越过阈值 | 新增的 gap 计数字段 > 100 | 前置条件 |
| 2 | 模式改变 | `mode = GLOBAL`（或 `TOOL_SPECIFIC`） | 前置条件 |
| 3 | TTL 由真实历史决定 | 手动重算 `_choose_empirical_ttl` 与记录值一致 | 机制自洽性 |
| 4 | 决策时确实使用了该 TTL | 同一 Entry 的 `deadline = ttl_decision + ttl` | 链路一致性 |

注：**`ttl != default_ttl` 不是历史机制有效的必要条件。**
经验 TTL 完全可能在某个决策上选中 `0`（本反事实中出现 2 次），或者数值上恰好等于默认值，
而机制依然是正确执行的。它是**诊断信号**，不是门禁。

### 2.2 一个可反驳的观测（而非普适预测）

> **观测：在本负载 + W1-A 历史分布下，Δq 中位 +0.0027、最大 +0.0030，
> q 排序改变 0/29（多候选 0/18），argmin 改变 0/18。**
>
> 这是对本轮数据的陈述，**不是**对“任何 History-Rich Replay”的预测。
> 已明确不成立的推论有三条：
>
> 1. q 排序未改变 **不代表** 任何 History-Rich Replay 中都不会改变；
> 2. q 数值变化小 **不代表** 评分排序一定不会变化（排序只取决于 q 之间的相对关系）；
> 3. 本反事实用的是 W1-A 的 gap 分布，M6 的 workload 会产生什么样的历史尚未确定。
>
> 可保留的只有上界部分（§2.3）；可被推翻的只有“本负载上未改变”这一条。
> 若 M6 的新 replay 出现明显不同的结果，应优先复核 §2.3 的推导与本轮的配对/need 恢复口径，
> 而不是直接采信任一方。

### 2.3 可证明的部分：一个上界（不是对 M6 的要求）

TTL 由 `_choose_empirical_ttl` 选出：

$$\text{ttl}^\*=\arg\max_{t\in\{0\}\cup\text{samples}}\big[\mathrm{CDF}(t)\cdot B-t\big],\qquad B=q_{\text{queue}}\cdot\eta+\text{prefill\_reload}$$

因为 `score(0) = 0`，要取正值必须 `CDF(t)·B > t`，故**必然 `ttl* < B`**。而

$$q=\sigma\!\left(\frac{\text{ttl}-\text{elapsed}}{\tau}\right)\Rightarrow|\Delta q|\le \frac{|\Delta\,\text{ttl}|}{4\tau}<\frac{B}{4\tau}$$

本数据中 `B` 中位 0.9076 s、最大 1.4392 s（`queue_delay = 0`，`η = 1`），`τ = 30 s`：

$$|\Delta q| < \frac{1.4392}{120} = 0.0120$$

与实测最大 0.00304 一致（实测更小，因为 sigmoid 在该区间未饱和）。

这个不等式说明的是：**在冻结 TTL 规则下，`Δq` 被 `B/(4τ)` 封顶。**
它能做到什么、做不到什么必须说清：

- 它**能**说明：若 `B` 在亚秒级，`Δq` 不可能超过 1.2%。
- 它**不能**说明：`Δq` 必须达到多少才能改变某个具体排序——那取决于该决策中 q 的实际差距，
  而 q 差距在各决策间差异很大（本数据 q 决策内跨度中位 0.441，但存在跨度小得多的决策）。
- 它**不是**对 M6 Workload 的硬性要求。M6 应基于自身 Workload、容量与压力设计决定
  `queue_delay` 与容量的取值；本文只指出：若目标是让 TTL 通道对 q 产生可观影响，
  需要 `B` 相对 `τ` 足够大。这是一个可检验的设计约束描述，不是验收阈值。

## 3. q 可引入的最有价值的一至两个信号

先排除（本轮及此前已证）：

| 候选信号 | 结论 | 依据 |
|---|---|---|
| E1a `native_cached_prefix_tokens > 0` | 在带 trace 的候选行上**恒为 1.0** | 负载首轮后 180/180 均 > 0 |
| E1b hash-LCP 复用率 | **恒为 1.0** | 每 program 内容固定，哈希链恒等 |
| E1c 复用块数 | 就是前一次块数 → 与 N 共线 | H1 495 对 |
| E6 prefix 增长速率 | v10 由 materializer 给定，H1 恒为 0 | 无实测变异 |
| Server gap history | 只能改 TTL，而 `Δq` 受 `B/(4τ)` 封顶 | §2.3 |

**关于 E1a 的重要限定**：`native_cached_prefix_tokens > 0` **不等于完整缓存命中**。
它表示前缀中**至少有一部分**命中（本负载常见值为 112 tokens，而 prompt 常达数千 tokens）。
因此把 E1a 读作“命中/未命中”会高估命中率，也会把部分命中当成完全复用。
若未来要用它，应同时记录 `cached / prompt` 比值与 `cached >= prompt - 1` 这类严格命中判定。

### 3.1 首选信号：**逐出后重取率（per-entry eviction → refetch rate）**

定义：对 Entry *i*，在历史中"曾被逐出"的周期里，统计其后被再次请求的比例

$$r_i=\frac{\#\{\text{evictions of } i \text{ followed by a re-request}\}}{\#\{\text{evictions of } i\}}$$

为什么是它：

1. **它就是 q 想代理的那个量。** 现行 q 估的是"未来会不会被用"；`r_i` 直接测"上次被逐出后有没有被用"。
2. **与 elapsed 独立。** 它按周期计数，不读时间戳；§1.3 的共线性问题不适用。
3. **变异来自真实负载。** 只要负载真的"逐出→重取"，`r_i` 天然在 [0,1] 上有分布；
   而现有负载从不 miss，所以 `r_i` 恒无定义——这正是"需要一个会丢内容的 workload"的原因。
4. **可归因。** 它的取值可以被 M6 的逐出/重取证据逐条核对，不需要信任模型。

需要的新观测：**每个 Entry 的逐出事件，以及随后同一 prefix 是否被再次请求**（§5.1 第 6 项）。

#### 使用 `r_i` 前必须先定义的六件事（否则不可实现，也不可归因）

本阶段**不批准实现** `r_i`。在实现之前，以下每一项都必须先写成契约：

| # | 项目 | 必须回答的问题 |
|---|---|---|
| 1 | **观察窗口** | 从什么时候开始计数？只算本 run，还是允许跨 run 预热？窗口长度上限是多少？ |
| 2 | **身份关联** | 「同一 Entry」用什么绑定？`(program_id, prefix_id)` 在重放中是否稳定？block 是物理槽位（可回收），不能作身份 |
| 3 | **右删失** | run 结束时「已逐出但尚未重取」的 Entry 算分母还是丢弃？当前 v10 存在 `W1B_RIGHT_CENSORED_REPLAY_WINDOW_ENDED`，必须明确规定 |
| 4 | **样本量** | 分母小于多少时不使用 `r_i`？护栏阈值如何定？ |
| 5 | **与 q 的语义关系** | `r_i` 与 `q` 是否测同一个量？若是，则它是 q 的**替代**而非**补充**，二者不能相加；若否，二者量纲不同（概率 vs sigmoid 代理），不能直接加权混合 |
| 6 | **去偏** | 逐出本身与压力等级相关，`r_i` 会被「谁被逐出得多」影响；是否需要按机会次数归一 |

第 5 项尤其重要：如果结论是「`r_i` 替代 q」，那么 A1+ 应写成 `R_i = r_i·N` 之类的形式，
而不是 `q_i·(…)`；这是两个不同的算法，不能混在一个 PR 里。

### 3.2 次选信号：**queue delay history（已有通道，缺数据）**

`_choose_empirical_ttl` 的 benefit 里已含 `queue_delay·η`，且 queue delay 在拥塞时可达秒级。

- 优点：零实现成本，已有 `queue_delay_t_seconds` 与 `queue_delay_history_sample_count`；
- 限制：它是 TTL 通道，不是独立于 elapsed 的复用信号；只改变 TTL 与 q 的量级，
  不改变「q 只在测 recency」这一结构事实。
- 是否值得启用是 **M6 Workload 设计的函数**，不是本报告能定的结论（§2.3）。

> **不推荐的信号**：Program 轮次/进度、工具类型、上下文长度。
> 前两者在决策时确实可用，但与 elapsed 强相关（任务越久，轮次越多）；
> 后者与 N 共线。加入它们等于给已有轴再加权，无法通过"独立信息"检验。

## 4. `q × N` 评分中最值得修正的结构性问题

按"值得改 / 改动小 / 可归因"排序。

### 4.1 问题一：λ 是**全局统一**的 overshoot 单价

$$R_i=q_i\big[\min(\text{need},N_i)+\lambda\max(0,N_i-\text{need})\big]=q_i\big[\lambda N_i+(1-\lambda)\min(\text{need},N_i)\big]$$

括号对 `N_i` 是仿射的，斜率恰为 λ。含义是：**每一块超额释放都按同一价格收费，
不管这一块是否可能被复用。** 这与代价的真实结构相反——超额释放的代价取决于它所在链的复用概率。

### 4.2 问题二：全部 sufficient 时，括号内只剩一个弱 N 项

`min(need, N_i) = need` 对每个候选相同 ⇒ 括号只剩 `λ(N_i − need)`，
而本数据 `N_i` 的候选间离散度仅 1.53×，远小于 q 的跨度（中位 0.441）。
所以排序主要由 `q_i` 决定。

但**不能推成“λ 无效”**：实测 λ=0 与 λ=0.5 在 **2/18** 个决策上选出不同答案（均 g05，§1.4）。
准确的说法是：**λ 的作用被压缩到一个窄区间，但在该区间边界（λ→0）仍能翻转少数决策。**
真正的问题不是 λ 取错，而是括号里缺少量纲正确的代价项：`N_i` 只是块数。

### 4.3 问题三：`N_i` 被当成"需要重算的块数"

必须分开的四个量（§1.5 已给实例）：

| 层 | 量 | 本数据中的关系 |
|---|---|---|
| 1 | Entry 解除保护（release） | 每个决策释放 1 个 Entry |
| 2 | **新增 eligible blocks `N_i`** | 200 / 1620（候选间 8.1×） |
| 3 | **真实物理 eviction** | 由 native 压力路径决定，本 run 1084 次 |
| 4 | **最终重算损失** | 仅当被逐出块之后被重新请求且 APC 未命中 |

`N_i` 只在第 2 层。把第 2 层当第 4 层用，是"成本代理不准确"的确切位置。

### 4.4 值得保留的部分

- `Sufficient-first` 的语义是对的：`min(need, N_i)` 保证"先满足压力需求"计满、超额部分打折。
- `Earliest Deadline` 与 `Minimum Overshoot` 分别覆盖了 q 轴与 N 轴的两个极端，
  因此**不要把 A1 改成它们的组合**，否则无法归因。
- λ=0 与 λ=1 的边界已明确：λ=0 ⇒ 只按 q 排序（`q·need`，常数因子）；λ=1 ⇒ 按 `q·N`。
  两者都是同一族的端点，不是不同算法。实测 λ=0 的 2 个分歧恰好落在 g05，
  说明端点差异在本数据上确实存在但很少。

## 5. 对 M6 的观测要求与验收判据

### 5.1 机制观测清单（必要，缺一项则该门禁不可判定）

| # | 观测项 | 字段要求 | 现状 |
|---|---|---|---|
| 1 | Server gap 样本数与来源 | `global_server_gap_sample_count`、`tool_server_gap_sample_count`、`provenance` | **缺**（只有 eta / queue 计数） |
| 2 | TTL 模式 | `TTLDecision.mode`、`reason` | **缺** |
| 3 | 每候选输入与分数 | `q_i`、`N_i`、**A1 实际使用的 `need`**、`λ`、`score_i`、`deadline_i`、`ttl_i`、`ttl_decision_ts` | **部分**（`selection_trace` 有 q/N/score，但**未直接记录 need**，需反解） |
| 4 | 多候选决策及分歧 | 与 A0 / Sufficient-first / Earliest-Deadline / Min-Overshoot 的选择对比 | **部分**（仅 29/600 带 trace） |
| 5 | 每次 pressure release 的新增 eligible | `newly_eligible_block_ids` 计数 | **已有** |
| 6 | **逐出 → 重取证据** | 每 Entry 的 eviction 事件（含 `(program_id, prefix_id)`）+ 之后同 prefix 是否被再请求 + APC 命中与否 | **缺**（决定 `r_i` 能否计算） |
| 7 | 物理逐出与重算 | `BLOCK_EVICTED`、`native_cached_prefix_tokens`、`prompt_tokens`、重算时长 | 部分 |
| 8 | 右删失标记 | run 结束时尚未重取的逐出记录如何标记 | **缺**（见 §3.1 第 3 项） |

**优先级**：

1. **必须补齐第 1、2 项**：否则历史机制门禁无法判定。
2. **强烈建议补齐第 3 项的 `need`**：目前需反解，能反解是因为本数据全部 sufficient；
   一旦出现 `N_i < need` 的候选，反解就会被饱和隐藏，产生偏差。
3. **第 6、8 项只在打算评估 `r_i` 时必须**；若本阶段不推进 `r_i`，可暂不实现。
4. 第 4 项应覆盖**所有**多候选决策，而不是仅 29/600。

### 5.2 两个门禁（M1 要求区分）

**门禁 H（历史机制门禁）** —— 算法是否获得了真实可用的复用历史

| 判据 | 通过条件 | 类型 |
|---|---|---|
| H1 | 至少一个决策的 `global_server_gap_sample_count > 100` | **门禁** |
| H2 | 该决策 `mode != COLD_START` | **门禁** |
| H3 | 用记录的历史手动重算 `_choose_empirical_ttl`，与记录值一致（±1e-9） | **门禁**（机制自洽） |
| H4 | 该 Entry 的 `deadline = ttl_decision_ts + ttl` 在 trace 中成立 | **门禁**（链路一致） |
| H5 | `ttl_seconds != default_ttl_seconds` | **诊断**，不作为必要条件：经验 TTL 可能正好选中 0 或与默认值数值相同，机制仍然正确 |

**门禁 D（决策机会门禁）** —— 算法是否真正存在多个有意义的合法选择

| 判据 | 通过条件 | 类型 |
|---|---|---|
| D1 | ≥2 个候选通过 legality 检查 | **门禁** |
| D2 | 前两名 `score` 差距 < 2× | **诊断**，仅用于标识“选择被强制”的决策比例；不是所有情况的硬门禁 |
| D3 | 至少一个决策与 Sufficient-first 或 Earliest-Deadline 的选择不同 | **诊断**，用于确认基线之间真有差别；基线全一致时应先怀疑基线实现，而不是宣布算法无差异 |
| D4 | 与 A0 存在分歧 | **诊断**，仅记录 |

**两个门禁的关系（必须写进结论）**：
- H 通过、D 不通过 → 说明历史恢复了但负载没有选择机会，**不能**据此判定算法有效或无效；
- H 通过、D 通过、A1 选择未变 → 必须能解释"为什么没变"（本轮给出可检验的解释：`Δq` 受 `B/(4τ)` 封顶，
  但该解释需针对具体决策的 q 差距逐条核对，不能一概而论）；
- H 不通过 → 后续任何结论都只关于 cold-start 行为，不能推广。

**明确不要求 A1 产生收益才通过门禁。** 门禁检验的是机制是否成立、行为是否可解释。

### 5.3 建议的 Smoke 失败条件

以下任一条出现即应停止并复核，而不是继续加 run：

1. 出现带 trace 的决策，但 `q` 与该 Entry 的 `deadline`、`ttl` 不自洽（机制记录错误）；
2. `mode != COLD_START` 但用记录的历史重算 `_choose_empirical_ttl` 得不出记录值（历史未真正参与）；
3. 决策的 `need` 与 `sum(newly_eligible)` 关系无法复现（`N_i` 口径漂移）；
4. 负载在首轮之后仍全部部分命中（`cached > 0`），以至于 `r_i` 与 E1a 都无定义，
   Smoke 对问题的检验力为零；
5. 逐出/重取事件缺少身份关联，无法将一次重取归到具体 Entry（`r_i` 不可计算）。

注意：**`ttl_seconds == default_ttl_seconds` 不是失败条件**。它可能只是经验 TTL 恰好选中 0，
或数值上碰巧相等。失败条件是“无法用记录的历史复现该 ttl”，而不是“ttl 等于默认值”。

## 6. 后续算法改进的首选方案与备选方案

### 6.1 首选：**A1+ v1 —— 只把 λ 变成逐候选估计**（本阶段不批准实现）

保留 `q` 与 `N` 的现有语义与形状，只把**全局常数 λ 换成逐 Entry 的 `λ_i`**：

$$R_i=q_i\Big[\min(\text{need},N_i)+\lambda_i\max(0,N_i-\text{need})\Big],\qquad \lambda_i=\hat r_i$$

其中 `r̂_i` 是 §3.1 的逐出后重取率（可用 Beta/拉普拉斯平滑避免 0/1 饱和）。

**这是候选方法，本阶段不批准实现。** 在实施前，下列条件必须先满足：

| # | 前置条件 |
|---|---|
| 1 | §3.1 的六项契约（观察窗口 / 身份关联 / 右删失 / 样本量 / 与 q 的语义关系 / 去偏）先写成书面契约 |
| 2 | 确认 `r_i` 与 `q` 的关系：若二者测同一量，A1+ 应把 q 替换为 `r_i`，而不是把两者相乘 |
| 3 | M6 提供 §5.1 第 6、8 项观测，并在 Smoke 中验证 `r_i` 有非退化分布 |
| 4 | 门禁 H 与 D 已在同一批 run 上通过，且已有“为何不改变选择”的逐条解释 |

为什么选它（在满足前置条件之后）：

| 优点 | 说明 |
|---|---|
| 最小改动 | 公式形状、`q`、`N` 语义、Sufficient-first 合规性全部不变 |
| 直接针对 §4.1 | 超额释放的单价改为"该 Entry 的复用概率"，而不是全局常数 |
| 可归因 | `λ_i` 与 `λ` 的差异是唯一变量；`λ_i ≡ λ` 时逐位退化为 A1 |
| 硬护栏自然 | 无逐出历史时 `λ_i = λ = 0.5`，A1+ 与 A1 逐位相同 |

**硬护栏**（必须写进实现契约）：`eviction_observations < k`（建议 k = 2）时 `λ_i = λ`。
这保证任何观测到的差异都只可能来自 `λ_i` 本身，满足 M1 的"可解释为何改变或不改变"。

**可证伪性质**：在现有负载上 `λ_i ≡ λ`（无逐出历史），所以 A1+ v1 应当与 A1 逐位相同。
任何差异都必须在新的、会丢内容的 replay 上才出现——可用于反向检验实现是否真的没改其它东西。

### 6.2 备选：**把代价项从块数换成预期重算秒数**

$$R_i=q_i\cdot\text{prefill\_reload}_i\cdot\Big[\min(\text{need},N_i)+\lambda_i\max(0,N_i-\text{need})\Big]$$

针对 §4.2/§4.3（`N_i` 不是代价）。但：

- 需要 §5.1 第 6、7 项的完整证据，成本高；
- 改变了"评分单位"（块 → 秒），会影响与 A0/A2 的可比性；
- 若首选方案已经在门禁 D 下产生可解释差异，则没有必要引入它。

**只有在首选方案在 H、D 双通过条件下仍不改变任何选择、且能证明原因是"代价项缺量纲"时，才启动备选。**

### 6.3 明确不做

- 不引入多信号特征组合或多参数评分（无法归因，且违反"不通过反复调参寻找正向结果"）；
- 不改 q 的 τ 去凑效果（τ 是冻结的设计尺度，改它等于换问题）;
- 不在 cold-start 未解除的数据上评估 A1+；
- 本阶段不实现 `r_i`、`λ_i`、A1+ v1 或备选方案中的任何一项。
