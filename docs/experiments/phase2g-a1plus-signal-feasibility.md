## 2. E1：先固定口径，再报实测

### 2.0 必须说明的定义漂移

上一版（H1 版）把 E1 定义为**命中率**，本版（M6 版）用的是**相邻复用率**。这是两个不同的量，
我在换数据源时一并换了口径却没有显式声明，属于遗漏。现在固定如下，后文每个数字都标出属于哪一个。

| 变体 | 定义 | 取值 | 回答的问题 | 能否用已入库数据算 |
|---|---|---|---|---|
| **E1a 命中率** | 该链先验请求中，native cached tokens > 0 的比例 | [0,1]，跳变 | 复用**是否发生** | **不能**（需 native 观测或 sidecar） |
| **E1b 复用率** | 相邻调用的精确token LCP ÷ 前一次 prompt 长度 | 近 1 的连续值 | 复用**占多少** | 能（W1-C 聚合表） |
| **E1c 复用量级** | 相邻调用的精确 token LCP 绝对数 | 数千 tokens | 复用了**多少** | 能（W1-C 聚合表） |

三者不可互换：

- E1a 是 0/1 平均值，对**miss** 敏感；E1b 对 miss 也敏感，但在 Agent 轨迹上
  只要 prompt 累积就会接近 1，所以两者“饱和”的成因不同；
- E1b 在 Agent 轨迹上接近同义反复：下一轮 prompt ≈ 上一轮 prompt + 工具输出，
  LCP 自然接近前一次长度。它更像是“上下文是累积的”的检验，而不是复用预测；
- E1c ≈ 前一次 prompt 长度，与 N 直接共线。

因此上一版的“E1 = 1.0 / 覆盖 8.3%”是 **E1a 在 H1 上**的结果，已随数据源一并撤回；
本版的 0.9709 / 0.9829 是 **E1b 在 W1-C 的本地分词上**的结果。
**E1a 在 M6 数据上尚未被测量过**，这是本轮没有回答、也不应假装回答的问题。

### 2.1 实测（W1-C 聚合，E1b 与 E1c）

W1-C pilot 聚合（40 runs / **2800 次成功模型调用** / 1407 次工具调用，均由脚本从 git 读出）：

| 条件 | 任务数 | 调用数 | 中位 prompt | 中位上下文增长 | 中位相邻精确 LCP | **中位相邻复用率** |
|---|---:|---:|---:|---:|---:|---:|
| S50 | 20 | 1000 | 5836 | 9131.5 | 5773 | **0.9709** |
| S100 | 20 | 1800 | 9245 | 17495.5 | 9209 | **0.9829** |

三点判断（均针对 E1b / E1c，不涉及 E1a）：

1. **作为比值（E1b），接近饱和。** 0.9709 → 0.9829，跨条件差仅 **+0.0120**。
   候选之间可用差异不到 3 个百分点，无法承担排序的主要权重。
   但要注意，它对 miss 仍然敏感：一次完全 miss 会把该对拉到 0，只是 W1-C 里几乎没有这种对。
2. **作为量级（E1c），与 N 共线。** 中位相邻 LCP 是 5773 / 9209 tokens，而中位 prompt 是 5836 / 9245。
   也就是说 E1c 约等于整个前缀长度，与现有评分里已使用的 N 高度重合，
   加进模型等于给 N 再加一次权重。
3. 因此在本数据上，E1b/E1c 的主要问题是**信息重复**，不是数据缺失。

同时必须说清限制：W1-C 的 token 是**本地确定性分词**，不是 Native 运行时提交观测
（报告原文 `PINNED_LOCAL_TOKENIZATION_NOT_NATIVE_SUBMISSION`）。
所以 E1b/E1c 测的是“复用潜力”，既不是 E1a，也不是真实命中。

## 3. E6（Prefix 增长速率）在真实轨迹上的实测

| 条件 | 中位每任务增长 (tokens) | 每任务调用数 | 隐含每调用增长 |
|---|---:|---:|---:|
| S50 | 9131.5 | 50 | ≈ 183 |
| S100 | 17495.5 | 90 | ≈ 194 |

- 预算翻倍（50 → 100 步）使**总增长**接近翻倍（9131 → 17495，1.92×），
  但**每调用增长**几乎不变（183 → 194，1.06×）。
- 因此在均值层面 E6 近似常数（约 190 tokens/轮），不随预算变化；
  不能用"增长快/慢"解释 S50 与 S100 的差异。
- E6 是否可用，取决于**跨任务**的每调用增长率离散度。
  已提交的聚合表只有中位数，**回答不了**；必须逐任务重算。

这是唯一仍值得投入的检查项，而它需要 sidecar。

## 4. 与 Entry 决策的映射（W1-C 自己列的边界）

W1-C 文档把下列量标为 `NOT_OBSERVABLE_FROM_TRAJECTORY_ONLY`：

```
decision-time candidate count
marginal newly_eligible_blocks
pressure requirement (need)
candidate q values / their span
A1 divergence from Earliest Deadline / Minimum Overshoot
Native APC eligibility, residency, eviction, recomputation
```

含义很直接：**即使拿到全部 sidecar，也只能把 E1/E6 算到"轨迹层"，
不能直接算成"Entry 决策时刻的特征"。** 从轨迹层到决策层还需要一次 Native replay，
因为候选集、`need`、q 的跨度都只在引擎内部产生。

所以本阶段可行性判断只能分两层给出：

| 层 | 能否离线判定 | 结论 |
|---|---|---|
| 轨迹层：E1/E6 是否有变异 | 能（聚合已有；逐调用需 sidecar） | E1 饱和且共线；E6 均值近常数 |
| 决策层：能否改变 Entry 排序 | **不能**（缺候选集与 `need`） | 待授权后的 Native replay |

## 5. 泄漏规则

| # | 泄漏 | 规避 |
|---|---|---|
| 1 | 用整段轨迹而非 `t` 之前的调用算 E1 | 只用 submit 时间早于决策时刻的调用 |

## 7. 最小实现方案（仅当 §6 的检查通过）

只改 q 的构造，λ / N 语义 / Block Selection / Native 路径一律不动。

1. 运行时按链维护（纯新增字段，不改变现有语义）：
   `observed_requests`、`reuse_pairs`、`mean_adjacent_reuse`、`mean_growth_tokens`。
   更新点与现有 `reuse_state` 相同（每次请求完成），只写当前值与计数。
2. `q' = (1-β)·q + β·f(E)`，β 冻结 0.5，不提供调参入口。
3. **硬护栏**：`observed_requests < 3`（不足两个相邻对）时 `q' = q`，
   与 A1 逐位相同，使任何差异只能来自信号本身。
4. 决策时记录 `e1_n / e1_value / e6_n / e6_value / q_base / q_used`，
   下一轮覆盖率审计不需要新的 Campaign。

## 8. 结论

1. **E1**：口径必须说清楚，三种变体的结论不同：
   - **E1b（复用率）**：0.97 / 0.98，跨条件差 0.012，接近饱和，且对 Agent 轨迹近乎同义反复；
   - **E1c（复用量级）**：相邻 LCP ≈ 整个前序 prompt，与 N 共线；
   - **E1a（命中率）**：**在两个可用数据集上都未被测量**，因此“E1 是否可预测复用”仍未回答。
   可说的是：E1b/E1c 提供的新信息很少，不建议作为主信号；E1a 需要 Native 观测才能判定。
2. **E6**：均值层面近似常数（≈190 tokens/轮，跨预算 1.06×）。
   是否可用取决于**跨任务离散度**，而聚合表不含该信息。
3. **两者都无法只靠轨迹判定能否改变 Entry 排序**：候选集、`need`、q 跨度
   被 W1-C 明确列为 `NOT_OBSERVABLE_FROM_TRAJECTORY_ONLY`。
4. **建议先做一件低成本的事**：让 M6 提供 W1-C 的 runs root（sidecar 目录），
   用现成脚本跑出跨任务 E6 离散度与 E1b/E1c 的逐调用分布。
   若离散度显著大于轮内噪声，再谈机制实现；
   若不足，则如实报告“两个候选信号均未提供足够的独立信息”，不为凑算法而拼特征。
   若要回答 E1a，则必须有一次带 native cached-token 观测的授权运行。
5. 本轮不给研究方向裁定，不申请 Campaign。

## 9. 三步诊断（M1 指定顺序）—— H1 / v10 全局口径

> **注**：本节在 H1 与 v10 全量数据上做。**§10 改为在 A1 臂上做**，
> 因为 A1 臂记录真实 A1 决策（`selection_trace`），而 H1 不记录。
> 两节结论在 A、B 上一致，在 C 上不同（H1 由块数主导，A1 由 q 主导）。
> **以 §10 为准**，本节保留作为对照与“H1 为何不适用”的证据。

脚本：`scripts/probes/entry_costaware_audit/three_diagnostics.py`。
数据：H1（唯一同时有 native cached tokens 与 native hash 链的数据集）+ v10（有 elapsed / prefill 载荷）。
两处口径修正已并入：E1 一律标注 a/b/c；`pressure:*` 程序不算 agent 链（它们各自内容是唯一的，
相邻 LCP 恒为 0，会污染 E1b 的集中度）。

### 9.1 E1 的分布是否集中：是，且只在"决策时刻"集中

请求级（agent 链，495 个相邻对）：

| 变体 | 取值数 | 众数占比 | 归一化熵 | CV |
|---|---:|---:|---:|---:|
| E1a 命中率 | 2 | 67.9% | 0.101 | 0.69 |
| **E1b hash-LCP 复用率** | **1** | **100.0%** | **0.000** | **0.00** |
| E1c hash-LCP 块数 | 10 | 17.6% | 0.353 | 0.74 |

决策级（只用先验观测）：

| 变体 | 取值数 | 众数占比 | CV |
|---|---:|---:|---:|
| E1a 命中率 | **1**（=1.0） | 100.0% | 0.00 |
| E1b 复用率 | **1**（=1.0） | 100.0% | 0.00 |
| E1c 链块数 | 10 | 17.2% | 0.75 |

三点：

1. **E1b 完全退化**：495/495 个 agent 相邻对的 hash 链 LCP 都等于前一次长度。
   原因是 H1 每个 program 只有一份固定内容，逐出后重算出来的 hash 链一模一样。
   所以 E1b 无法区分"内容存在"与"内容在缓存里"。
2. **E1a 在请求级有真实变异**（336 命中 / 159 未命中），但**在决策时刻被删失**：
   能算的 39 行全部为 1.0，因为第二次请求一定发生在压力之前，那时没逐出。
   这解释了上一版"H1 上 E1 恒为 1"——是窗口问题，不是信号问题。
3. **E1c 只是块数**（10 个取值），与 N 同源。

> 判断：在可用的决策时刻切片上，E1 的任何变体都**没有候选间差异**，
> 因此它在此数据上不可能改变排序。这个否证是**关于切片**的，不是关于信号本身。

### 9.2 E1 / E6 与 elapsed 是否高相关：E1 不是，但 q 就是 elapsed

先验证一个代数事实：

```text
max |elapsed - (t - deadline)| = 0.000e+00        (n = 471)
```

`ttl = 0` ⇒ `deadline = 上次 TTL 决策时刻` ⇒ `q = sigmoid(-elapsed / 30)` **精确成立**。

| 配对 | Spearman | n |
|---|---:|---:|
| elapsed vs **q**（决策级） | **−1.0000** | 39 |
| elapsed vs E1a（请求级） | −0.1169 | 495 |
| elapsed vs E1c（请求级） | +0.0653 | 495 |
| elapsed vs E1c（决策级） | −0.1201 | 39 |

结论分两半，都很明确：

- **q 与 elapsed 完全共线（|ρ|=1，且是代数恒等）**，所以"在 q 里再加一个 elapsed 的代理"必然无效。
- **E1a / E1c 与 elapsed 几乎无关（|ρ| ≤ 0.12）**，所以它们**不是** recency 的伪装，
  这一点对 A1+ 是有利的——它们携带的是正交信息，只是这份数据里没有变异。
- **E6 无法测**：H1 的块差恒为 0（无方差），v10 的块差由 replay 生成器给定。
  两者都不能回答"增长速率是否只是 elapsed 的函数"。

### 9.3 候选之间的实际重算代价差异是否够大：够大，但杠杆不在 q

每个决策内做 max/min（只算 ≥2 候选的决策）：

| 量 | H1 中位 | H1 p90 | v10 中位 | v10 p90 |
|---|---:|---:|---:|---:|
| `prefill_reload` | **4.60×** | 14.50× | 1.71× | 6.39× |
| 块数 | **6.00×** | 16.00× | 1.52× | 7.86× |
| **q 绝对跨度** | **0.00087** | 0.0144 | **0.441** | 0.500 |
| q max/min（q > 1e-6） | **1.002×** | 1.030× | 6.78× | 886× |
| `q × prefill` | 4.62× | 14.50× | 10.51× | 2170× |
| 最优/最差 ≥ 2× 的决策 | **81 / 114（71.1%）** | | 14 / 16（87.5%） | |

两方面都要说：

1. **代价差异确实大。** H1 里 71% 的决策，最优与最差候选的期望重算代价相差 2 倍以上，
   中位 4.6 倍。所以"选对 victim"是有实义的，不是无关紧要。
   而且这 4.6 倍几乎全部由 `prefill_reload`（4.60×）与块数（6.00×）贡献。
2. **但 q 这个杠杆在 H1 里几乎不存在**：q 的 max/min 中位只有 **1.002×**，绝对跨度 0.00087。
   换句话说 H1 的排序实际上由 `prefill_reload × 块数` 决定，q 只是一个近乎常数的乘数。
   这也正是 λ 调参与几何平均都无收益的**实测**原因（不只是代数原因）。
3. v10 相反：q 跨度中位 0.441（elapsed 最长到 594 s），所以 v10 里 q 是主要杠杆之一。
   而且 v10 **确实有** native cached-token 观测（`VLLM_NATIVE_REQUEST_OBSERVATION`，
   每 run 13 条），所以 E1a 在那里可算——这一点上一版写错了，已在 §10 更正。

> 三步合起来给出的判断很干脆：
> **A** 决策时刻 E1 无候选间差异（E1b 退化、E1a 被删失、E1c 就是 N）；
> **B** q 与 elapsed 是同一个量，E1 与 elapsed 正交但无变异；
> **C** 代价差异足够大（71% 的决策 ≥2×），但 H1 里 q 只有 1.002× 的杠杆，
> 所以**改 q 构造在 H1 几何下几乎不可能改变任何决策**；
> 要让它有意义，必须先在 q 真正有杠杆（如 v10 的 elapsed 跨度）且 E1a 可观测的条件下测量。

### 9.4 由此产生的实现前门槛（建议由 M1 裁定）

| 门槛 | H1 | v10（全部决策） | **v10 A1 臂（真实 trace）** |
|---|---:|---:|---:|
| 决策时刻 E1a 跨候选有差异的比例 | 0% | 可算（见 §10） | **0%**（47 行全为 1.0） |
| q 的决策内 max/min ≥ 1.1× | 中位 1.002×，达标率极低 | 中位 6.78× | 跨度中位 0.441 |
| 代价最优/最差 ≥ 2× | 71.1% | 87.5% | 16/18（非退化子集 9.9× 中位） |

H1 同时缺"E1a 有变异"和"q 有杠杆"两项；v10 有"q 有杠杆"，
而且 E1a **可算**——只是算出来恒为 1.0（见 §10）。
所以"没有任何数据集能回答"这句话要修正为：
**能测量的地方 E1a 无变异；E1a 有变异的地方（H1 请求级）不在决策时刻。**

## 10. 改在 A1 臂上做：三步诊断（替换 H1）

脚本：`scripts/probes/entry_costaware_audit/a1_three_diagnostics.py`。
数据：v10 bounded 的 **A1 臂**（18 runs），即真实 A1 决策发生的地方。

### 10.1 为什么 A1 臂比 H1 强

| 能力 | H1 | v10 A1 臂 |
|---|---|---|
| 真实 A1 决策记录 | **无**（H1 无 `selection_trace`） | **有**，29 条带 trace |
| 每候选的 q | 需按公式复算 | **直接记录**在 trace 里 |
| 每候选的 `expected_recompute` / `new_blocks` | 只能从块数推 | **直接记录** |
| native cached-token 观测 | 有（但决策时刻被删失） | **有**（每 run 13 条） |
| q 的决策内杠杆 | 中位 1.002×（几乎为常数） | 跨度中位 **0.441** |

先更正上一节的一处事实错误：v10 **有** native cached-token 观测。
`VLLM_NATIVE_REQUEST_OBSERVATION` 每 run 13 条，三臂各 234 条，带
`native_cached_prefix_tokens` 与 `native_prompt_tokens`。
之前写"v10 无 cached token，E1a 不可算"是错的。

### 10.2 覆盖：有效样本是 18 个决策

| 项 | 数量 |
|---|---:|
| A1 释放决策 | 600 |
| 带 `selection_trace` | 29 |
| **带 ≥2 个候选（真正有选择）** | **18** |
| 每 trace 候选数 | 1 个 × 11，2 个 × 18 |
| 有 trace 的 run 数 | 18（每 run 1–2 条） |

571 个决策只释放单一候选，无法承载"信号能否改变排序"的比较。
**瓶颈是样本量，不是可观测性** —— 这一点与之前几轮的判断不同，需要明确。

### 10.3 A. E1 分布是否集中：是，而且是因为负载本身不产生 miss

先看负载的原始复用结果（agent program，排除 `pressure:*`）：

| | a0 | a1 | a2 |
|---|---|---|---|
| 首个请求命中 | 18 / 36 | 18 / 36 | 18 / 36 |
| 之后所有请求命中 | **180 / 180** | **180 / 180** | **180 / 180** |

两点与 H1 完全不同：

1. **首个请求也会命中**（18/36，`cached = 112` tokens）。原因是 v10 的两个 program
   共享一段 112 token 的公共前缀，所以"命中"不必来自同 program 的重复。
   在 H1 里首个请求恒为 miss（537/537）。
2. **之后所有请求都命中**，三臂一致。也就是说**该负载在首轮之后从不 miss**。

因此按 A1+ 口径计算的 E1a：

| 项 | 值 |
|---|---|
| 参与评估的候选行 | 47 |
| 每行的先验观测数 | **全部为 5** |
| E1a 取值 | **恒为 1.0**（1 个取值，CV = 0） |

> **结论：E1a 在 A1 臂上可测，但恒为 1.0。
> 退化来自负载没有复用失败，而不是来自观测窗口被删失。**
> 这与 H1 的机理不同（H1 是删失），但判定相同：该信号在本数据上无法区分候选。

### 10.4 B. E1 / E6 与 elapsed 的相关性：q 就是 elapsed，E1 不相关（因为不变）

先验证公式，用 trace 里记录的 deadline 与决策时刻重算：

```text
max |sigmoid((deadline - t)/tau) - 记录 q| = 0.000e+00     (n = 47)
```

| 配对 | Spearman | n |
|---|---:|---:|
| elapsed（= t − deadline）vs **q** | **−1.000000** | 47 |

**q 与 elapsed 是同一个量**：`elapsed = t − deadline`，
`q = sigmoid((deadline − t)/30) = sigmoid(−elapsed/30)`，代数恒等，不是统计相关。

- E1a 与 elapsed 的相关性**无法计算**，因为 E1a 在这 47 行上没有方差；
  这不是"相关性低"，是"没有可比较的变异"。
- **E6 仍不可测**：v10 的前缀长度由 replay materializer 给定，增长速率描述的是生成器。
- q 的分布在这里是有杠杆的：跨候选 11 个取值，决策内跨度中位 0.441、最大 0.5。
  **所以 A1 臂是理论上能让新信号起作用的地方**，只是 E1a 恰好没有信息。

### 10.5 C. 候选之间的重算代价差异是否够大：够大，但含退化成分

18 个有 ≥2 候选的真实 A1 决策：

| 量 | p50 | p90 | max |
|---|---:|---:|---:|
| `expected_recompute` max/min（全部） | 16.33 | 1.419e+09 | 1.631e+09 |
| `expected_recompute` max/min（< 1e6） | 9.87 | 2114 | 2144 |
| `new_blocks` max/min | 1.53 | 8.1 | 8.1 |
| `expected_recompute` 绝对差（< 1e6） | 235.2 块 | 405.2 | 414 |
| 最小值为近零的决策 | **2 / 18** | | |
| 前两名相差 < 2× 的决策 | **4 / 18** | | |

读法：

1. 代价差异总体很大（非退化子集中位 **9.87×**，绝对差中位 235 块），
   所以"选对"确有实义。
2. 但 1e9 量级的比值来自 q 塌缩到 ~1e-9 的候选：这类候选的
   `expected_recompute ≈ 0`，A1 必然选它，**任何新信号都改不了**。
   把它与正常决策混在一起统计会夸大"差异够大"的印象。
3. `new_blocks` 的 max/min 只有 1.53（中位），说明在这批决策里候选的块数差异不大，
   **起决定作用的是 q（即 deadline）**。这与 §9.2 在 H1 上发现的相反。

### 10.6 三步诊断在 A1 臂上的合并判断

| 诊断 | A1 臂结果 | 与 H1 相比 |
|---|---|---|
| A 分布集中 | E1a 恒 1.0（负载无 miss） | 机理不同（删失 vs 无失败），结论相同 |
| B 与 elapsed 相关 | q ≡ elapsed（代数恒等）；E1a 无方差 | 一致 |
| C 代价差异 | 非退化子集 9.87×，但 2/18 为 q 塌缩 | 杠杆由 q 主导，而非块数 |

由此：

- **A1 臂是可行的实验位置**，因为它记录真实 trace 且 q 有杠杆；
- **但 E1a 在该负载上无信息**（全部命中），所以在这里也验不出"E1 能否改变排序"；
- **E6 依旧不可测**；
- **真正的限制是 18 个选择点**，任何"信号有效/无效"的结论都只有这个样本量。

### 10.7 因此下一步的建议（仍不申请 Campaign）

1. **不要再用 H1 做信号实验** —— 它连 A1 决策都没有记录。
2. **A1 臂可作为唯一可用的验证位置**，但在动 q 构造之前，先解决两件事：
   - **样本量**：18 个选择点不足以判定任何信号。需要扩大 run 数，或让 A1 在
     更多时刻面临 ≥2 候选（当前压力集中在 615 s 一次）。
   - **E1a 无变异**：需要在会产生 miss 的负载上测（例如真的逐出后继而被复用，
     而不是首轮之后全命中）。当前 v10 负载在首轮后从不 miss，这是**负载性质**，
     不是实现问题。
3. 若坚持在现负载上验证信号，只能验证与 miss 无关的信号；E1a 不在其列。
