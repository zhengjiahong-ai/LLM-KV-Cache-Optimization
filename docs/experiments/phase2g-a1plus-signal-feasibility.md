# Phase 2G A1+ —— E1 / E6 离线可行性判断

**范围**：只回答"这两个候选信号是否存在、能否在 Entry 释放决策之前拿到、是否携带独立信息、是否泄漏"。
未修改 A0/A1/A2，未新增 λ、未改 N 语义、未改 Block Selection 与 Native 路径，未启动任何 Campaign。
**结论先行：现有离线数据不支持直接进入实现阶段。** 原因不是信号被否证，而是两个信号在唯一的实测数据里都没有变异。

分析脚本：`scripts/probes/entry_costaware_audit/e_signal_feasibility.py`（只读，可重复运行）。

## 0. 数据基础

| 数据集 | 规模 | 能支持什么 | 位置 |
|---|---|---|---|
| H1 Level-A | 126 runs / 1068 条 native APC 观测 / 120 个 Entry 释放决策 | 真实 cached-token 结果、真实 hash 链、真实决策载荷 | `local/phase2a-h1-level-a-evidence-e3a02fd/`（gitignored） |

关键事实：H1 的 1068 条观测里，**每条链的首个请求从不命中**（537/537），

`max_new_tokens = 1` 使模型输出不累积进后续前缀。

## 1. 候选信号的实际覆盖率

决策时刻（`FORCED_RELEASE_DECISION`）实际记录的状态：

| 量 | 值 |
|---|---|
| Entry 释放决策 | 120（其中 114 个有 >1 个候选） |
| 候选行 | 471 |
| 决策时候选链的先验观测数 | **1 条：432 行；2 条：39 行** |
| `waiting_followup` | **True 471 / 471** |

覆盖率：

| 信号 | 定义 | 已定义行 | 行覆盖率 | 已定义决策 | 决策覆盖率 |
|---|---|---:|---:|---:|---:|
| `E1_hit_rate` | 先验请求中命中比例（需 ≥2 条先验） | 39 | **8.3%** | 33 | **27.5%** |
| `E1_last_outcome` | 最近一次先验请求是否命中（需 ≥1 条） | 471 | 100%，但见 §2 | 120 | 100% |
| `E6_blocks_per_turn` | 先验相邻观测的块数差均值（需 ≥2 条先验） | 39 | **8.3%** | 33 | **27.5%** |

**约束来自时序，不是来自可观测性。** 432 行的唯一先验请求就是该链的第一次请求，
而第一次请求按构造不可能命中（此前没有任何内容可复用）。
只有压力发生在第二轮之后的 39 行（分布在 8 个 scenario draw × 3 seeds），
才存在一次真实的复用结果可读。

## 2. 数值分布

| 信号 | n | min | median | max | 不同取值 |
|---|---:|---:|---:|---:|---:|
| `E1_hit_rate`（已定义处） | 39 | 1.0 | 1.0 | 1.0 | **1** |
| `E1_last_outcome` | 471 | 0.0 | 0.0 | 1.0 | 2 |
| `E6_blocks_per_turn`（已定义处） | 39 | 0.0 | 0.0 | 0.0 | **1** |
| `elapsed_since_ttl_decision` | 471 | 0.0026 s | 1.72 s | 3.31 s | 471 |
| `q = σ((deadline−t)/30)` | 471 | 0.472422 | 0.485667 | 0.499979 | 471 |

两个分布都是退化的，但原因不同，且必须分开说：

- **E1 = 1.0（全部 39 行，跨 8 个 scenario draw）**：这不是“E1 恒为真”的证据，
  而是**观测窗口被截断**的结果。链上要两条先验观测才能算 E1，
  而第二条请求发生在压力抵达该链之前——在那之前内容不会被逐出，所以**必然命中**；
  压力一到，决策就在下一条请求之前触发，于是再也拿不到新的观测。
  换言之，在本数据里 E1 只能在“尚未受压”的窗口里被测到，
  而那个窗口内复用总是成功。E1 因此**无法取到 0 值**，也无法据此估计其判别力。
- **E6 = 0.0（全部）**：H1 每条链的块数差值恒为 0（`(0,)`×321、`(0,0)`×87）。
  v10 的差值恒为生成器给定的线性斜坡（25–383 块/轮，46 个不同取值）。
  两个数据集里 E6 的变异都不是负载产生的。

注：471/471 个候选的 `waiting_followup` 都是 True，这意味着在这些决策点上
“该 program 会回来”已经是冻结输入里的事实，E1 不可能比它多提供这一层信息。

## 3. 与原 q 的相关性

q 在决策时刻只有 **0.0276** 的动态范围（0.4724–0.5000），全部挤在 0.5 以下的窄带里。
原因是代数性的：`COLD_START` 的 `ttl_seconds` 是初始化常数，
`deadline = 上次 TTL 决策时刻`，`elapsed` 只有 0.003–3.3 s，除以 τ=30 s 后落在 (−0.11, 0)。

| 配对 | 结论 |
|---|---|
| Spearman(q, E1) | **不可计算**：39 个样本里 E1 只有一个取值 |
| 候选块数 N | 1–32，中位 12，10 个不同取值 |

因此在现有决策点上，A1 的排序实际由 **N** 主导，q 只提供不到 0.03 的微扰。
这同时解释了为什么 λ 调参与几何平均都无收益：它们都在一个几乎不起作用的轴上做重标定。

## 4. 能否改变 Entry 排序

| 检查 | 结果 |
|---|---:|
| 至少 2 个候选带 E1 的决策 | 6 |
| 其中 E1 在候选之间有差异 | **0** |
| `q' = E1` 时 argmin 改变 | **0** |
| `q' = q/2 + E1/2` 时 argmin 改变 | **0** |

6 个可测决策里两个候选的 E1 都是 1.0，q 只差 0.0003 左右。**排序无法被改变，因为没有差异可依。**

## 5. 信息泄漏

已识别的四类，按危险程度排序：

| # | 泄漏方式 | 后果 | 规避规则 |
|---|---|---|---|
| 1 | 用整段 run 的 cached-token 计算 E1，而非 `timestamp < t` | E1 会"预测"它自己读过的答案 | 只允许严格早于决策时刻的观测 |
| 2 | 用 trace 的 `is_terminal` / 未来轮次重建"该 program 是否继续" | 直接把标签当特征 | 不得读取 trace 的规划字段 |
| 3 | 跨 run 汇总历史 | H1 的 126 个 run 复用同一批 trace，跨 run 历史等于同一序列的副本 | 不得跨 run 池化，除非有独立的来源声明 |
| 4 | 只给一个 arm 加特征 | A0/A1/A2 不可比 | 特征必须三臂同构，含 A0 |

补充一条与本次数据直接相关的：`elapsed_since_ttl_decision` 与 `waiting_followup`
已经是冻结输入的一部分，任何由它们派生、或与它们同义的量都不构成新信息。
E1 在可测量的 6 个决策上正是这种情形。

## 6. 关于 M1 提出的两件事

### 6.1 几何平均与 λ 调参（同意，且可给出代数理由）

排序若按 $\sqrt{qN}$，与按 $qN$ 完全等价，因为平方根严格单调。
带权形式 $q^{w}N^{1-w}$ 等价于比较 $w\log q+(1-w)\log N$，只是重新分配两项权重，
不引入新信息。而在 §3 的实测中 q 的动态范围仅 0.0276，
任何对 log q 的重新加权都只是在 N 轴上移动阈值。

### 6.2 W1-A 的 443 条历史（区分两种 gap）

| 维度 | W1-A | v10 replay |
|---|---|---|
| gap 来源 | 相邻两次模型调用的真实间隔，中间夹着 mini-swe-agent 的 shell 工具执行 | trace 的 `tool_gap_seconds` **全为 0**，下一轮由完成事件驱动 |
| 观测值 | 中位 0.2799 s，p90 0.3638 s，max 58.1 s | 中位 0.2825 s，p90 1.6635 s，max 4.58 s |
| 性质 | **agent gap**（工具延迟 + 排队） | **runner gap**（harness 周转开销） |

两者中位数接近但尾部完全不同，且生成机制不同，所以 W1-A 不能默认适用于 W1-C。
另外：**W1-A 无法支撑 E1/E6** —— 归档只保留了 gap 数值，
模型调用的 sidecar 里有时间戳但没有 token 或前缀字段。

公平性要求：若启用 warm-start，必须对 A0/A1/A2 同时注入同一份历史，
并在配置里绑定 SHA-256；warm-start 只能改变 TTL 历史输入，不能改变臂间差异。

## 7. 最小实现方案（仅当数据支持时）

**范围**：只改 q 的构造。λ、N 语义、Block Selection、Native 路径一律不动。

1. 在 Entry 决策输入里增加每链计数（纯新增字段，不影响现有语义）：
   `observed_requests`、`reuse_events`、`prefix_blocks_prev`、`prefix_blocks_last`。
   更新点与现有 `reuse_state` 相同（每轮请求完成时），只写入，不回溯。
2. 定义 `q' = (1-β)·q + β·E1`，β 冻结为 0.5，不提供调参入口。
3. **硬护栏**：当 `observed_requests - 1 < 2` 时 `q' = q`，
   即在数据不足处与 A1 逐位相同。这条护栏保证 A1+ 在无法支持信号的地方不改变行为，
   从而任何观测到的差异都只可能来自信号本身。
4. 决策时记录 `e1_n / e1_value / e6_n / e6_value / q_base / q_used`，
   使下一轮覆盖率审计不需要新 Campaign。

**进入实现前的量化门槛**（建议由 M1 裁定，本文只是提出）：

| 条件 | 当前值 |
|---|---:|
| 覆盖率 ≥ 30% 的决策 | 8.3% |
| 决策内 E1 有差异的比例 ≥ 10% | 0% |

两项均未达到。

## 8. 结论

1. **E1**：机制上可取（每链计数器即可），但现有数据里**覆盖只有 33/120 决策**，
   且在被覆盖的那部分恒为 1（观测窗口被截断所致），
   6 个可测决策内无候选间差异，因此**无法证明它能改变排序**。
   与 `waiting_followup` 的关系需在实现前单独论证，不能假定二者不同。
2. **E6**：**不可评估**。H1 的轮间块差恒为 0，v10 的轮间块差由生成器给定；
   两个数据集都不含真实的前缀增长变异。
3. 二者都**不能**用 W1-A 补足：该归档只保留 gap，没有 token 或前缀字段。
4. 因此本阶段**不建议**进入机制实现，也**不建议**为凑出新算法而组合特征。
   建议的下一步只有两条，且都需要 M1 授权：
   - 先加 §7 第 4 项的日志字段，在下一次（已授权的）运行中测量真实覆盖率；
   - 或者提供一个含真实多轮前缀增长的轨迹来源，再用本脚本重跑一遍。
5. 本轮不给研究方向的最终裁定。
