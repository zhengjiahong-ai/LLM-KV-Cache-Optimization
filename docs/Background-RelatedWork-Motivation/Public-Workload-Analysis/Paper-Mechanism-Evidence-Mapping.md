# Continuum 机制与 Nebius 公开轨迹的证据映射

## 结论

这套真实 SWE Issue 执行轨迹支持 Continuum 的工作负载动机。67,074 次尝试的可见 Assistant 请求中位数为 61，并且工具交互在后续输入中累积大量可重用文本。观察到自然提交的尝试中，执行进度与剩余请求数有较强的描述性关联，`η = 0.711`。范围限于 OpenHands 软件工程负载和可见请求序列。论文的 TTL、GPU 排队、实际重算时延及调度收益仍需时间与 Serving Runtime 数据。[Continuum v6](https://arxiv.org/html/2511.02230v6) · [固定版本公开数据](https://huggingface.co/datasets/nebius/SWE-rebench-openhands-trajectories/tree/35455389ab51bf5e2306bfd436ef72d0f98bf882)

## 多轮结构与删失

完整 Parquet 扫描核对了 4,316,962 条 Assistant 消息。每条可见 Assistant 消息界定一次重建请求。每行是一次 Program 尝试，6,306 个 Issue 包含重复尝试。数据没有独立 serving Session 或请求重试身份。PR #135 的历史增长序列来自同一 SHA-256 Parquet。相对 Program 四分段的相邻 LCP 中位数为 12,995、26,304、37,089、48,799 tokens。样本中工具结果占新增内容字符的 76.43%。[初始报告](Nebius-OpenHands-Trajectories.md)

| 观测结束 | 尝试 | 均值 Turn | P50 / P90 / P95 | 解释 |
| --- | ---: | ---: | --- | --- |
| other_interruption | 332 | 46.99 | 43 / 73 / 82.45 | 其他中断，后续未知 |
| step_limit | 6,003 | 99.05 | 100 / 100 / 100 | 原始状态显式上限，后续未知 |
| submit | 60,739 | 61.03 | 59 / 84 / 90 | 观察到提交动作 |

5,954 条尝试观测到 100 轮，其中 5,750 条报告到达上限、204 条报告提交。6,003 条上限记录中有 253 条可见 Assistant 数小于 100，OpenHands iteration 和可见请求的计数口径因此不能互换。其余 332 条中断单列。`resolved` 是补丁验收，与是否还有请求属于不同标签。

## η 估计与敏感性

以每个 Program 的可见模型请求为 ordinal，使用 `k=1,…,N` 的快照，按快照估计 Pearson 相关。另给每次尝试总权重相同的估计，以及自然提交中去掉终止快照的估计。主区间为 1,000 次按 Issue 整簇重抽样的百分位区间，保留一簇内所有重试。区间描述该归档的 Issue 聚类变异，未校正分布外、Repository 共同效应或截断选择。100 轮上限对照与假设性扩展分别呈现。

| 范围或假设 | 尝试 | 快照加权 η | 尝试等权 η | Issue 聚类 95% 区间 |
| --- | ---: | ---: | ---: | --- |
| 自然提交 | 60,739 | 0.711 | 0.693 | 0.707–0.715 |
| 自然提交，去掉终止快照 | 60,739 | 0.704 | 0.684 | — |
| 自然提交且 <100 轮 | 60,535 | 0.715 | 0.696 | — |
| 全归档观测末端代理 | 67,074 | 0.655 | 0.628 | 0.651–0.660 |
| 全表，非提交者假设多 10 轮 | 67,074 | 0.598 | 0.583 | — |
| 全表，非提交者假设多 25 轮 | 67,074 | 0.500 | 0.507 | — |
| 全表，非提交者假设多 50 轮 | 67,074 | 0.337 | 0.373 | — |

扩展行只衡量 `N` 未知对相关量的影响。它们改变非提交者的假设终点和快照数，不生成消息、填补时间或进入在线输入。达到上限组末端代理 η = 0.988，近固定的采集长度会把组内相关推向 1。按已知总长分层的较高 η 也有同一数学原因，在决策时不能使用该组别。真实提交且到达 24、64、90 轮者的平均剩余可见请求数分别为 37.03、12.86、4.42。这是各阶段不同风险集上的回顾量，不能直接等同于在线剩余工作预测。

| <=25 | 1 | 25.00 | 1.000 |
| 26-50 | 17,176 | 43.62 | 0.937 |
| 51-75 | 32,096 | 61.61 | 0.928 |
| 76-99 | 11,262 | 85.22 | 0.964 |
| 100+ | 204 | 100.00 | 1.000 |
| bash_more | 46,008 | 60.35 | 0.709 |
| editor_more | 12,422 | 64.13 | 0.733 |
| tie | 2,309 | 57.77 | 0.690 |

数据无可信的 bug / feature / refactor 类型标签。按 Repository 做任务来源敏感性分析，常见来源中 `tobymao/sqlglot` 的 2,075 次提交平均 71.60 轮、η 0.814，`python-pillow/Pillow` 的 1,167 次提交平均 64.92 轮、η 0.743，其余非头部 Repository 合计 55,485 次、η 0.708。工具占优是行为分层，Repository 是来源分层，两者分别提供异质性线索。完整分层与检查点风险集见 [memoryfulness.json](evidence-results/memoryfulness.json)。

工作量与资源机会是两件不同的可测量对象。公开轨迹可帮助选取长链、短链及继续深度不同的输入，项目侧 [Phase 1B 基线](../../experiments/phase1b-continuum/final-report.md) 和 [架构](../../architecture.md) 则定义了实际服务要测量的状态。若要检验 TTL 或调度目标，应观测同一时钟的完成/入队/服务时间、工具标识、实际提交输入及 block 状态，并在同一负载下配对比较。
