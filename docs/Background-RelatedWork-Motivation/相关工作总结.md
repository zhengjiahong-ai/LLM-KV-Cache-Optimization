## 1. 研究背景：KV 缓存的内存瓶颈

LLM 自回归生成依赖 KV 缓存保存历史 token 的 Key/Value 张量，以避免重复计算。缓存占用随上下文长度和并发请求数近似线性增长，而 GPU 显存高度受限，因此**缓存不够用时逐出谁**成为服务系统的核心决策问题：被逐出的缓存若再次被需要，必须重新执行计算密集的预填充（prefill），直接推高首词延迟（TTFT）。

两个基础事实框定了研究范畴：

- PagedAttention 论文指出，传统连续分配方式下 KV 缓存内存利用率低至 20.4%。分页机制改善了块的存放和回收方式，但论文未给出按重算损失排序的逐出策略；
- SAGA 论文在其 SWE-bench Agent 实验中报告，vLLM v0.6.0 有 38% 的执行时间用于在 Agent 步骤间重建 KV 缓存。这说明不合适的保留或逐出会带来明显开销。

## 2. 相关工作：按决策机制分三类

### 2.1 逐出类：主要使用访问历史或随机性

**LRU / Leaf-LRU**：LRU 按最后访问时间选择候选；在前缀树中，Leaf-LRU 还要求优先从叶子 token 中选择。RLT 论文以 SGLang 的 Leaf-LRU 为对象，证明它在特定前缀共享和到达顺序假设下的最坏竞争比为 \(O(n)\)。这类策略不直接估计候选块被逐出后的重算时间。

**ARC（Recency-Frequency Adaptive KV Caching）**：在新近度之外引入频率信号，用双队列加幽灵缓存反馈自适应调整两者的空间配比，缓解不相关负载互相冲刷缓存的问题。局限：其信号回答的是"会不会再被访问"，而不是"被逐出后再访问要花多大代价"；自适应只针对访问模式，对显存压力等系统状态没有反馈。

**RLT（Randomized Leaf Token Eviction）**：在未标记的叶子 token 中随机选择逐出对象，用随机性减弱对到达顺序的依赖。其结论针对前缀共享结构和论文设定的动态或对抗性到达；该随机选择本身不估计单个候选的重算成本。论文中的 LBGR 则属于请求路由层面。

### 2.2 保留与工作流感知类：延长复用窗口，并结合调度或逐出

**Continuum（TTL / retention）**：针对 Agent 工具调用期间缓存易被提前逐出的情况，Continuum 用请求间隔历史、排队延迟与重算开销估计 TTL，并在 TTL 内保留对应程序 / 会话前缀的 KV 缓存。TTL 到期后解除保护；内存不足时还会解除保护或释放部分受保护条目/前缀，以避免死锁。其主要决策是保留多久，不是对所有可逐出块逐一排序。论文在其多轮 Agent 设置下报告最高约 2.0 倍的平均作业完成时间改善。

**SAGA（工作流原子调度 + WA-LRU）**：SAGA 把 Agent 工作流作为调度单元。它用工具类型延迟分位数设置 TTL，并在显存压力下缩短 TTL；WA-LRU 则结合 AEG 给出的未来复用概率、新近度和缓存大小做逐出排序。论文在 SWE-bench 上相对 vLLM+APC 报告 1.73 倍任务完成时间改善。AEG 可由框架提示提供，也可由历史 trace 推断，因此需要额外的工作流信息或推断模块；其 WA-LRU 分数不直接建模候选块的重算时间。

**与本项目的关系**：Continuum 的重点是决定保留时长，SAGA 同时包含工作流感知的逐出排序。本项目拟在容量不足时，以运行时观察到的成本和复用信号排序候选块。两条路线可以组合。

### 2.3 工程提案：vLLM RFC #37003（保留指令）

vLLM 社区提案允许上层编排器对指定 token 范围下发驱逐优先级与生存时间（retention directives），以缓解 Agent 工作流下 LRU 误清会话前缀的问题。它属于"由调用方自顶向下声明重要性"的路线，与本项目"由系统在线估计重要性"的路线互补；该提案的存在也说明本问题已受到社区关注。

## 3. 局限性总结：共同的空白

| 策略类别 | 代表工作 | 决策信号 | 与本项目目标的差距 |
| --- | --- | --- | --- |
| 逐出类 | LRU、ARC、RLT | 时间戳 / 频率 / 随机 | 不直接估计候选块的重算时间 |
| 保留与工作流感知类 | Continuum、SAGA | 工具统计 / AEG / 调度状态 | 关注保留窗口或工作流预测，信息需求更高 |

在本文比较的工作中，尚未发现同时满足以下条件的方法：在逐出时刻，只依赖本地运行时可观测信号，并直接估计每个候选块的重算损失。这是本项目拟检验的切入点。

## 3.1 潜在未来研究方向

本项目另保留四条尚未授权的未来研究方向：证据感知的 Block 策略介入、工作流运行时信号驱动的 Block 选择、下游成本感知的 Entry 释放顺序，以及 Partial-tail Entry unpinning。它们分别涉及 Block 策略控制、Block 信息建模、Entry 释放排序和 Entry 保护粒度，不属于当前 Phase 3 六臂实验。详细研究问题、实现缺口和验证要求见 [Potential Future Research Directions](../future-research-directions.md)。

## 4. 相关工作与本项目的对应关系

### 4.1 当前实验中的系统基础与对照

早期文档曾把 Native vLLM 与 Continuum-style adaptation 写成两个并列“Baseline 1/2”，并规划全系统比较。当前 Phase 3 的实际结构更精确：

- **Native vLLM 0.27.1 APC + Native LRU + Native scheduler** 是共同执行底座和物理块选择基线；N0 是不执行强制 Entry Release 的控制臂。
- **A0** 是项目侧 Continuum-style Entry Release + Native LRU 物理块选择，作为当前 Entry Release 政策对照。它不是完整公开 Continuum 系统，也不是与 Vanilla vLLM 的全系统对比。
- **A1/A3/E0** 在 Entry Release 层比较注册的成本感知/后缀成本/截止时间策略；**A2** 只改变物理 Block Victim Selection，并保留 A0 Entry Release。

ARC、RLT、SAGA 仍作为相关工作和机制参照，不是当前 Phase 3 六臂中的直接实验组。

### 4.2 当前研究定位与贡献边界

本项目是在项目侧 Continuum-style cache-management adaptation 内研究成本感知决策。系统先利用 program/session、工具间隔历史、动态 TTL 与软留存维护多轮缓存生命周期；在内存压力下，再分别考察两个决策：

- **Entry Release：** 哪个受保护的逻辑条目应先解除保护；
- **Physical Block Victim Selection：** 在 Native 合法候选中实际选择哪些物理 KV 块。

两者不是同一个决策层。Phase 3 的 A1/A3/E0 改变 Entry Release，A2 改变物理块选择；所有臂使用 Native scheduler。是否降低重算量由冻结的 270-run campaign 与独立 N/E/C evaluator 判断，在结果接受前不得声称成本感知方法优于基线。
