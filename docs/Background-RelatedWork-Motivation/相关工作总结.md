# 相关工作总结

项目研究面向 vLLM 的 Continuum 风格 KV Cache 管理成本感知优化。Phase 1B 的 Continuum-style adaptation 提供 program/session 生命周期、Dynamic TTL、软保护和压力释放。Phase 3 在这条管理路径中分别研究逻辑 Entry Release 与 Physical Block Victim Selection。逐篇机制和实验条件见[论文总结](References&Notes/论文总结.md)，比较口径见[对比笔记](References&Notes/对比笔记.md)。

## 1. KV Cache 基础设施与前缀共享

PagedAttention 通过非连续的物理 Block 管理 KV Cache，使动态分配和块共享成为可能。GPU APC 通过前缀内容与哈希复用已计算的 KV。分页描述存储布局，APC 描述跨请求复用，Physical Block Victim Selection 则在可回收候选中选出实际 victim。历史论文中的序列抢占和恢复不能用于推断 vLLM 0.27.1 的 GPU APC 驱逐顺序。见 [vLLM 参考文档](References&Notes/参考文献/关于vLLM的参考文档与网址.md)。

## 2. 替换策略与访问历史

LRU 只需最近访问顺序。在活跃会话频繁提交相同前缀时，recency 本身就有较强的预测力。ARC 通过驻留队列与 ghost hit 调整新近度和频率的空间配比。RLT 利用标记与随机性改变 radix tree 的叶子替换，论文中的 LBGR 则用负载和时延估计做跨 worker 路由。三者的比较主要解释替换信号或到达结构的作用，不能回答逻辑 Entry 应何时解除保护。

## 3. Agent 工作流的保留与调度

- **Continuum** 从 program 生命周期出发，以历史请求间隔、排队等待和重算/载入代价估计 TTL。TTL 决定保留窗口，压力下的解除保护和 program-level scheduling 处理不同的资源约束。项目在 Phase 1B 适配了这些机制，保留 Native vLLM 对物理分配与清理的所有权。A0 的项目侧 Entry Release 顺序冻结为 `(Entry deadline, newly eligible Blocks 的 minimum Native LRU rank, deterministic Entry identity)`；若释放某 Entry 不产生新增资格 Block，第二键按正无穷处理。这里的 Native rank 只在 deadline 相同时参与 Entry 排序，物理 Block victim selection 仍使用 Native LRU。该规则是项目适配，不是 Continuum 论文 §5.2 的 latest-program-arrival 死锁预防规则。见[基线冻结](../baseline-freeze.md)。
- **SAGA** 用 AEG 或 trace 推断获得工作流信息，组合工具感知 TTL、WA-LRU 与集群调度。WA-LRU 是替换排序，session affinity 和 work stealing 则决定调度与负载分布。其完整系统结果无法用于估计当前 Phase 3 中单一决策层的收益。

## 4. 面向 Agent 的缓存管理

- **KVFlow** 将编排层提供的 Agent Step Graph 映射为 steps-to-execution，对 radix tree 的 KV node 排序，并为即将运行的 Agent 重叠 CPU→GPU 预取与计算。
- **CacheWise** 分析闭环 coding Agent 的前缀复用与工具间隔，使用工具及运行时元数据预测复用，同时用驻留前缀长度决定请求准入优先级。完整系统比较与固定调度后的驱逐消融应分别阅读。

这两项工作提供不同的前视信号。工作流结构、工具元数据与训练数据的可得性取决于部署，信号在项目 TTL 模块中出现也不代表 A2 已在 Block 决策时使用它。

## 5. 复杂替换的增量价值

WFEF 的生产 trace 评估显示，多种复杂替换策略在作者测试的容量和负载下接近 LRU。小容量时也有 quick demotion 策略表现更好的反例。其 compute-aware partial-node eviction 研究的是缓存移除粒度，可以启发代价建模，不能直接验证逻辑 Entry 的尾部解除保护。引用结果时应保留容量、trace 和指标条件。见[论文总结 §8](References&Notes/论文总结.md)。

## 6. 项目的比较范围

这些文献可比较决策层、信息需求与实验设计。系统间的加速比受模型、硬件、容量、负载、路由、调度与预取共同影响。项目的性能证据来自同一冻结输入与配置下的 Native 配对比较。A0 提供适配系统中的 Entry Release 基线，A2 保持该路径并比较 Block Victim Selection。Phase 3 的六臂和报告口径见 [Protocol v4](../phase3-final-evaluation-protocol-v4.md)。进一步的信号、介入和保护粒度问题收录于[潜在未来研究方向](../future-research-directions.md)。
