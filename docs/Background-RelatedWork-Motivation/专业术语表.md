# 专业术语表（团队统一口径）

> **文档定位（2026-11-10）**：本表统一当前项目术语。项目定位为“面向 vLLM 的 Continuum 风格 KV Cache 管理成本感知优化”。Continuum-style lifecycle/retention 是系统基础；当前 Phase 3 分别评估逻辑 Entry Release 与物理 Block Victim Selection。旧文档中的“Cost-Aware KV Cache Eviction”及“Baseline 1/2”属于早期研究语境，不应覆盖当前 [研究定位](../research-motivation-and-contributions.md)、[状态账本](../research-status.md) 与 [Protocol v4](../phase3-final-evaluation-protocol-v4.md)。

---

## 1. 基础架构与显存管理

| 术语（中文/英文） | 缩写/标识符 | 标准定义与系统作用 |
| --- | --- | --- |
| **KV 缓存** *KV Cache* | KV Cache | 自回归推理中缓存的历史 token 的 Key/Value 张量，用于避免重复计算；其显存占用随上下文长度与并发数近似线性增长，是本项目研究的对象。 |
| **预填充** *Prefill* | Prefill | 对输入历史做一次完整前向计算的阶段，计算密集；缓存块被逐出后再次被需要时必须重做，因此是"重算成本"的主要来源。 |
| **物理驱逐** *Physical Eviction* | Eviction | 从 Native KV cache 中实际移除物理缓存块以回收空间的动作；与仅解除逻辑 Entry 的保护状态不同。Native vLLM 仍负责 BlockPool、free queue、ref-count、APC hash 与清理记账。 |
| **物理块 / 逻辑条目** *Physical Block / Logical Entry* | Block / Entry | 物理块是显存中的 KV 存储单元；逻辑条目是 Continuum-style retention 管理的程序/会话前缀状态。当前研究同时涉及逻辑 Entry Release 与物理 Block Victim Selection，不能把二者都简称为“逐块驱逐”。 |
| **分页注意力** *PagedAttention* | PagedAttention | vLLM 提出的机制，把逻辑连续的 KV 缓存切成固定大小物理块非连续存放，解决碎片问题；它是驱逐策略的运行基础，本项目不修改该机制本身。 |
| **自动前缀缓存** *Automatic Prefix Caching* | APC | 按 token 内容及前缀计算哈希实现跨请求块共享（如共享系统提示词）的机制；共享前缀正是"重算昂贵"块的典型来源。 |
| **引用计数** *Reference Count* | ref_cnt | 记录当前有多少活跃请求正在引用某物理块；`ref_cnt > 0` 的块不得被驱逐，这是所有候选策略（含基线）必须遵守的硬约束。 |
| **物理驱逐候选** *Physical Eviction Candidate* | — | 通过 Native 引用计数及保护/资格约束、可进入物理 victim selector 的 KV block 集合。A2 在合法候选中选择物理 victim；Entry Release 的候选对象是逻辑 retention entry，二者不可混用。 |

## 2. 驱逐策略与传统算法

| 术语（中文/英文） | 缩写/标识符 | 标准定义与系统作用 |
| --- | --- | --- |
| **最近最少使用** *Least Recently Used* | **LRU** | 按最后访问时间选择物理驱逐候选的策略。Phase 3 中 N0/A0/A1/A3/E0 使用 Native LRU 物理 victim selection；A2 才替换这一层的选择器。 |
| **成本感知缓存管理策略** *Cost-Aware Cache-Management Policy* | — | 当前 Phase 3 的成本感知优化覆盖两个不同决策层：A1/A3/E0 对逻辑 Entry Release 作出选择，A2 对物理 Block Victim Selection 作出选择。具体策略语义以 Protocol v4 为准；是否带来收益仍是待正式实验回答的问题。 |
| **自适应替换缓存** *Adaptive Replacement Cache* | **ARC** | 以新近度、频率双队列加幽灵缓存反馈自适应分配空间的替换算法（Recency-Frequency Adaptive 一文）；本项目仅作对比参照，说明"自适应"仍不含重算成本信号。 |
| **随机叶子驱逐** *Randomized Leaf Token Eviction* | **RLT** | 在未标记叶子 token 中随机选择逐出对象的算法（Randomization-Boosts-KV-Caching 一文）。它是理解随机化如何改善特定前缀共享负载下 LRU 最坏情况的理论参照。 |
| **工作流感知 LRU** *Workflow-Aware LRU* | **WA-LRU** | SAGA 提出的驱逐排序机制，结合 AEG 预测的重用概率、新近度和缓存大小。它需要工作流信息或相应推断模块，不直接按候选块的重算时间排序。 |
| **虚假驱逐** *False Eviction* | — | 缓存仅因暂时无人访问（如 Agent 等待工具返回）即被逐出、随后又立即被需要的现象；是本项目动机中的核心失败模式。 |
| **软留存 / 硬锁定** *Soft Retention / Hard Pinning* | — | 软留存指带时限或优先级、在资源紧张时可解除的保留；硬锁定指无条件禁止驱逐，可能造成显存耗尽。vLLM 0.27.1 无原生 pin API，故 Continuum 风格基线的冻结适配是"项目独立保护表 + 驱逐候选过滤"：受保护块仍留在原生 free queue 中并保留 APC 哈希元数据，**禁止**用抬高 `ref_cnt`、移入隐藏池或复制 BlockPool 记账来模拟 pin。见 `docs/baseline-freeze.md` §6。 |

### 2.1 当前研究中的两个决策层

| 术语（中文/英文） | 缩写/标识符 | 标准定义与系统作用 |
| --- | --- | --- |
| **逻辑 Entry Release** *Logical Entry Release* | Entry Release | 解除某个受保护逻辑 retention entry 的保护，使其关联的 Native blocks 变为可参与物理 victim selection 的候选；该动作本身不等于物理块已被淘汰。 |
| **物理 Block Victim Selection** *Physical Block Victim Selection* | Victim Selection | 在 Native 合法候选物理 KV blocks 中选择实际 victim 的决策层。Phase 3 A2 改变此层；其余臂使用 Native LRU。 |
| **N / E / C** | N, E, C | N 为 native prompt tokens，E 为 independently qualified reusable eligible native-prefix tokens，C 为 native cached-prefix tokens；满足 0 ≤ C ≤ E ≤ N。三者必须独立建立证据。 |
| **Workload Group** | Group | Phase 3 的独立统计单位。C1/C2 cells、turns 与 runtime repeats 都不是额外独立 Group。 |

### 2.2 潜在未来研究方向术语

| 术语 | 标准定义与边界 |
| --- | --- |
| **Evidence-aware Block Intervention** | 证据感知的 Block 策略介入：在证据充分、候选集完整、确实改变 victim set 且预期收益超过门槛时才启用自定义 selector；不同于已有的输入/契约 Fail-Closed fallback。未来研究方向，未实现、未授权。 |
| **Workflow-aware Block Signals** | 工作流运行时信号驱动的 Block 选择：研究决策时可用的工具上下文、请求间隔、排队延迟等信号是否在 TTL deadline 之外提供增量价值；不等于使用 SAGA/KVFlow 的外部 AEG/ASG。未来研究方向，未实现、未授权。 |
| **Downstream-cost-aware Entry Release** | 下游成本感知的 Entry 释放：对候选 Entry 释放进行 lookahead，模拟实际下游 Block selector 产生的 victim set，并估计其后续重算损失。未来研究方向，未实现、未授权。 |
| **Partial-tail Entry Unpinning** | Entry 尾部部分解除保护：仅解除某个 Entry 的后缀 Block range 保护，同时保留浅层前缀保护；改变的是 eligibility，不是物理 eviction。未来研究方向，未实现、未授权。 |

## 3. 成本与经济效用模型

| 术语（中文/英文） | 缩写/标识符 | 标准定义与系统作用 |
| --- | --- | --- |
| **成本异构性** *Cost Heterogeneity* | — | 不同缓存内容被逐出后可能产生不同重算代价（例如共享前缀长度不同）；这是研究动机与潜在收益来源，不等于当前实验已经证明存在可利用的性能收益。 |
| **重算成本** *Recomputation Cost* | — | 缓存未命中后重新预填充所需的时间与计算开销。它是成本感知决策的通用概念；Phase 3 各 arm 的具体输入与估计契约以 Protocol v4 为准，不应假定所有 arm 都使用同一个逐块在线成本估计。 |
| **复用信号** *Reuse Signal* | — | 描述缓存条目或物理块未来可能再次被使用的信息，是成本感知缓存管理中的通用概念。Phase 3 的各策略是否使用复用相关信息、如何使用，必须按各 arm 的冻结契约描述；不能将早期“统一从近期历史估计”的设想视为所有 arm 的共同实现。 |
| **内存足迹** *Memory Footprint* | — | 一个缓存条目或物理块集合占用的显存大小。它是成本感知缓存管理中可讨论的通用因素；不得据此推断所有 Phase 3 arm 都显式使用该信号，具体输入以冻结策略契约为准。 |
| **缓存压力** *Cache Pressure* | — | 当前缓存容量与分配需求之间的紧张程度。Phase 3 的 C1/C2 是冻结 operating-point 名称，分别绑定 256/1024 required_blocks；不要将其直接重命名为低/高压力。 |
| **在线估计** *Online Estimation* | — | 仅使用决策时已经可获得的运行时信息进行估计。该术语用于描述算法设计约束；当前 Phase 3 各 arm 的实际输入与可用信息边界以 Protocol v4 为准，不代表所有 arm 均采用同一在线估计器。SAGA 的 AEG 来源属于其论文机制。 |
| **生存时间** *Time-to-Live* | **TTL** | Continuum-style adaptation 用于估计程序/会话前缀保护窗口的动态时长。Phase 1B 实现了带历史输入与明确近似来源的动态 TTL；这是项目侧适配的一部分，不应写成“精确复现 Continuum”或“Phase 3 已证明动态 TTL 优于静态 TTL”（Phase 3 没有 Static-TTL arm）。 |
| **逐出代价 / 驱逐损失** *Eviction Loss* | — | 逐出物理块或释放逻辑条目可能造成的预期后续损失，是研究动机中的通用概念。早期文档中的“重算成本 × 复用概率”仅为概念性示意，不是当前 Phase 3 所有 arm 的统一评分公式；具体决策函数与输入必须引用 Protocol v4 对应 arm 的冻结定义。 |
| **记忆度** *Memoryfulness* | **eta** | Continuum TTL 目标函数中刻画程序剩余轮次可预测性的因子。Phase 1B 冻结定义为 `eta = -PearsonCorr(k, N-k)`，样本取自已完成程序的每个非终止轮；允许为负值且**不得裁剪到 [0,1]**；无法计算时回退 `eta = 1`（记录为 `source = APPROXIMATED`，原因码 `reason = FULLY_MEMORYFUL_COLD_START`）。见 `docs/archive/phase1b-continuum/phase1b-continuum-implementation-decisions.md` §1.6。 |

## 4. 智能体工作负载相关

| 术语（中文/英文） | 缩写/标识符 | 标准定义与系统作用 |
| --- | --- | --- |
| **智能体工作负载** *Agentic Workload* | — | 以"思考—行动—观察"循环为特征的多轮任务负载（如编程、浏览器智能体）；与长上下文、多轮对话并列为本项目关注的三类负载。 |
| **工具调用** *Tool Call* | — | Agent 请求外部工具执行并等待返回的动作；执行期间 LLM 推理暂停，其 KV 缓存暂时无人访问，是虚假驱逐的高发场景。 |
| **挂起期** *Idle Pause* | — | 工具调用期间模型推理暂停的时间窗；保留类策略（Continuum/SAGA）正是针对该窗口设计，本项目以此解释基线的适用场景。 |
| **多轮对话** *Multi-Turn Conversation* | — | 同一会话内多次请求共享历史上下文的负载形态；会话越长前缀越贵，误逐一次的损失越大。 |
| **智能体执行图** *Agent Execution Graph* | **AEG** | SAGA 用于预测未来复用概率的工作流结构图。论文可从框架提示获得 AEG，也可由历史 trace 推断；本项目拟不接入此类工作流图。 |

## 5. 性能指标与评估

| 术语（中文/英文） | 缩写/标识符 | 标准定义与系统作用 |
| --- | --- | --- |
| **首词延迟** *Time To First Token* | **TTFT** | 请求提交到首个输出 token 返回的时间。它是重要的 serving-level 辅助指标，但不是当前 Phase 3 的注册主指标。 |
| **缓存命中率** *Cache Hit Rate* | — | 成功复用缓存的输入 token 或请求比例；可用于描述缓存行为，但不是当前 Phase 3 的注册主指标。 |
| **吞吐量** *Throughput* | — | 单位时间内完成的请求（或 token）数；与延迟指标一起构成服务质量的两面。 |
| **每 token 输出耗时** *Time Per Output Token* | **TPOT** | 解码阶段平均每生成一个输出 token 的耗时；用于排查驱逐策略对解码路径的副作用。 |
| **端到端延迟 / 完成时间** *End-to-End Latency / JCT* | JCT | 单个请求（或整个多轮任务）从提交到完成的总耗时；多轮场景下关注任务级完成时间。 |
| **重算量** *Recomputed Tokens* | — | 因 eligible prefix 未被 Native APC 复用而需要重新 prefill 的 token 量。当前 Phase 3 注册主指标为 Σ(E−C)，其中 N、E、C 必须独立推导；不得从 C 反推 E。 |
| **驱逐次数** *Eviction Count* | — | 实验中发生的驱逐事件数及被逐块/被逐 token 量；用于归因分析不同策略的驱逐行为差异。 |
| **策略决策开销** *Policy Decision Overhead* | — | 驱逐选择本身消耗的额外时间与内存（如排序、元数据维护）；成本感知策略必须证明收益大于该开销。 |
| **消融实验** *Ablation* | — | 通过移除或替换某个机制来识别其增量作用的实验方法。它是通用方法学概念；当前 Phase 3 只支持 Protocol v4 明确注册的六臂对比，不应把未注册的任意信号消融写成已授权实验。 |
