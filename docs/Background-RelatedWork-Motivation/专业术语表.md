# 专业术语表（团队统一口径）

> **文档定位**：本项目（Cost-Aware KV Cache Eviction for LLM Serving）内部统一口径的术语表。团队文档、PPT 与最终报告中涉及下列术语时，以本表定义为准。仅收录本项目研究语境中需要统一口径的关键名词；仅在外部论文中出现、本项目不使用也不讨论的概念（如 SAGA 的 Agent Fair Share、Continuum 的记忆度因子）不收录。

---

## 1. 基础架构与显存管理

| 术语（中文/英文） | 缩写/标识符 | 标准定义与系统作用 |
| --- | --- | --- |
| **KV 缓存** *KV Cache* | KV Cache | 自回归推理中缓存的历史 token 的 Key/Value 张量，用于避免重复计算；其显存占用随上下文长度与并发数近似线性增长，是本项目研究的对象。 |
| **预填充** *Prefill* | Prefill | 对输入历史做一次完整前向计算的阶段，计算密集；缓存块被逐出后再次被需要时必须重做，因此是"重算成本"的主要来源。 |
| **驱逐** *Eviction* | Eviction | 缓存空间不足时移出部分缓存块以腾出空间的操作；本项目拟在这一决策点改进候选块排序。 |
| **物理块 / 逻辑块** *Physical / Logical Block* | Block | 物理块是显存中固定大小的缓存存储单元，逻辑块是请求上下文中的缓存段，两者通过块表映射；**块是本项目的驱逐决策粒度**。 |
| **分页注意力** *PagedAttention* | PagedAttention | vLLM 提出的机制，把逻辑连续的 KV 缓存切成固定大小物理块非连续存放，解决碎片问题；它是驱逐策略的运行基础，本项目不修改该机制本身。 |
| **自动前缀缓存** *Automatic Prefix Caching* | APC | 按 token 内容及前缀计算哈希实现跨请求块共享（如共享系统提示词）的机制；共享前缀正是"重算昂贵"块的典型来源。 |
| **引用计数** *Reference Count* | ref_cnt | 记录当前有多少活跃请求正在引用某物理块；`ref_cnt > 0` 的块不得被驱逐，这是所有候选策略（含基线）必须遵守的硬约束。 |
| **驱逐候选** *Eviction Candidate* | — | 满足驱逐前提（如引用计数归零）的块的集合；*本项目方法的目标即在该集合内按驱逐损失排序选择牺牲块。* |

## 2. 驱逐策略与传统算法

| 术语（中文/英文） | 缩写/标识符 | 标准定义与系统作用 |
| --- | --- | --- |
| **最近最少使用** *Least Recently Used* | **LRU** | 按最后访问时间选择逐出候选的策略；本项目的 Baseline 1 采用 vLLM 风格的 LRU。该策略不直接估计不同候选的重算时间。 |
| **成本感知驱逐策略** *Cost-Aware Eviction* | — | *本项目拟提出的方法*：在驱逐时刻在线估计每个候选块的驱逐损失，优先逐出损失最小者；具体评分函数尚未冻结。 |
| **自适应替换缓存** *Adaptive Replacement Cache* | **ARC** | 以新近度、频率双队列加幽灵缓存反馈自适应分配空间的替换算法（Recency-Frequency Adaptive 一文）；本项目仅作对比参照，说明"自适应"仍不含重算成本信号。 |
| **随机叶子驱逐** *Randomized Leaf Token Eviction* | **RLT** | 在未标记叶子 token 中随机选择逐出对象的算法（Randomization-Boosts-KV-Caching 一文）。它是理解随机化如何改善特定前缀共享负载下 LRU 最坏情况的理论参照。 |
| **工作流感知 LRU** *Workflow-Aware LRU* | **WA-LRU** | SAGA 提出的驱逐排序机制，结合 AEG 预测的重用概率、新近度和缓存大小。它需要工作流信息或相应推断模块，不直接按候选块的重算时间排序。 |
| **虚假驱逐** *False Eviction* | — | 缓存仅因暂时无人访问（如 Agent 等待工具返回）即被逐出、随后又立即被需要的现象；是本项目动机中的核心失败模式。 |
| **软留存 / 硬锁定** *Soft Retention / Hard Pinning* | — | 软留存指带时限或优先级、在资源紧张时可解除的保留；硬锁定指无条件禁止驱逐，可能造成显存耗尽。Continuum 风格基线使用带 TTL 的 pin/unpin 语义。 |

## 3. 成本与经济效用模型

| 术语（中文/英文） | 缩写/标识符 | 标准定义与系统作用 |
| --- | --- | --- |
| **成本异构性** *Cost Heterogeneity* | — | 不同缓存块被逐出后的重算代价差异显著这一性质（如万级 token 共享前缀与几十 token 对话尾部）；*本项目立项的核心痛点与预期收益来源。* |
| **重算成本** *Recomputation Cost* | — | 缓存未命中后重新预填充所需的时间与计算开销；本项目拟以被逐块对应的缓存长度/块数作为代理量进行在线估计，不追求精确建模。 |
| **复用信号** *Reuse Signal* | — | 块在未来被再次使用的可能性；本项目拟从在线维护的近期复用历史中估计，不依赖任何先验工作流信息。 |
| **内存足迹** *Memory Footprint* | — | 一个缓存条目占用的显存大小；逐出足迹大而价值低的块可以一次释放更多空间，拟作为驱逐损失的修正项。 |
| **缓存压力** *Cache Pressure* | — | 当前显存占用的紧张程度；拟作为驱逐决策的输入，使策略响应全局状态，并用于负载配置（高/低压力场景）。 |
| **在线估计** *Online Estimation* | — | 只使用决策时可获得的运行时信号进行估计的方式。本项目拟以此估计成本和复用信号；SAGA 则使用 AEG 或基于 trace 的 AEG 推断。 |
| **生存时间** *Time-to-Live* | **TTL** | 为缓存设置的保留时长。Continuum 在 TTL 内 pin 对应请求的 KV 缓存，TTL 到期后解除 pin；内存不足时还可提前解除部分 pin。它是本项目复现的 Baseline 2。 |
| **逐出代价 / 驱逐损失** *Eviction Loss* | — | 逐出某块带来的预期损失，概念上约为"重算成本 × 复用概率"并受内存足迹与缓存压力修正；*本项目评分函数的目标形式，具体公式尚未冻结。* |

## 4. 智能体工作负载相关

| 术语（中文/英文） | 缩写/标识符 | 标准定义与系统作用 |
| --- | --- | --- |
| **智能体工作负载** *Agentic Workload* | — | 以"思考—行动—观察"循环为特征的多轮任务负载（如编程、浏览器智能体）；与长上下文、多轮对话并列为本项目关注的三类负载。 |
| **工具调用** *Tool Call* | — | Agent 请求外部工具执行并等待返回的动作；执行期间 LLM 推理暂停，其 KV 缓存暂时无人访问，是虚假驱逐的高发场景。 |
| **挂起期** *Idle Pause* | — | 工具调用期间模型推理暂停的时间窗；保留类策略（Continuum/SAGA）正是针对该窗口设计，本项目以此解释基线的适用场景。 |
| **多轮对话** *Multi-Turn Conversation* | — | 同一会话内多次请求共享历史上下文的负载形态；会话越长前缀越贵，误逐一次的损失越大。 |
| **智能体执行图** *Agent Execution Graph* | **AEG** | SAGA 用于预测未来复用概率的工作流结构图。论文可从框架提示获得 AEG，也可由历史 trace 推断；本项目拟不接入此类工作流图。 |

## 5. 性能指标与评估

| 术语（中文/英文） | 缩写/标识符 | 标准定义与系统作用 |
| --- | --- | --- |
| **首词延迟** *Time To First Token* | **TTFT** | 请求提交到首个输出 token 返回的时间；直接受缓存命中与重算开销影响，是本项目的核心结果指标。 |
| **缓存命中率** *Cache Hit Rate* | — | 请求的输入 token 中成功复用现有缓存、免于重算的比例；本项目的主要缓存行为指标。 |
| **吞吐量** *Throughput* | — | 单位时间内完成的请求（或 token）数；与延迟指标一起构成服务质量的两面。 |
| **每 token 输出耗时** *Time Per Output Token* | **TPOT** | 解码阶段平均每生成一个输出 token 的耗时；用于排查驱逐策略对解码路径的副作用。 |
| **端到端延迟 / 完成时间** *End-to-End Latency / JCT* | JCT | 单个请求（或整个多轮任务）从提交到完成的总耗时；多轮场景下关注任务级完成时间。 |
| **重算量** *Recomputed Tokens* | — | 因缓存未命中而重新预填充的 token 总量；*本项目分析因果链（更少昂贵误逐 → 更少重算 → 更低延迟）的关键中间指标。* |
| **驱逐次数** *Eviction Count* | — | 实验中发生的驱逐事件数及被逐块/被逐 token 量；用于归因分析不同策略的驱逐行为差异。 |
| **策略决策开销** *Policy Decision Overhead* | — | 驱逐选择本身消耗的额外时间与内存（如排序、元数据维护）；成本感知策略必须证明收益大于该开销。 |
| **消融实验** *Ablation* | — | 逐一关闭评分函数中的信号分量（如仅重算成本、仅复用信号、完整模型）以定位收益来源；实验计划的硬性要求。 |
