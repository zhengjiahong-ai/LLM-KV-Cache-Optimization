# 专业术语表（团队统一口径）

> **文档定位**：本项目内部统一口径的术语表。团队文档、PPT 与最终报告中涉及下列术语时，以本表定义为准。
>
> **本表的核心纪律**：严格区分**逻辑层**（Entry、逻辑前缀、保护状态）与**物理层**（物理 Block、驱逐、APC 命中）。逻辑释放（unpin）不等于物理驱逐（eviction）；获得驱逐资格（eligibility）不等于被实际移除（victim selection）。写错层级是本项目最常出现、也最致命的表述错误。
>
> **项目主线**：Entry 级保护释放与 Block 级物理驱逐的两层决策研究。四个研究方向见 [`kv_cache_optimization_motivation_and_design_proposal.md`](kv_cache_optimization_motivation_and_design_proposal.md)，动机见 [`项目动机文档.md`](项目动机文档.md)。
>
> 仅收录本项目研究语境中需要统一口径的关键名词；仅在外部论文中出现、本项目不使用也不讨论的概念不收录。

## 1. 两级决策对象（本项目最易混淆的一组）

| 术语（中文/英文） | 缩写/标识符 | 标准定义与系统作用 |
| --- | --- | --- |
| **保留条目** *Retention Entry* | Entry | Continuum 风格机制中受保护的最小逻辑单位，以 `(program_id, prefix_id)` 为键（代码：`RetentionEntrySnapshot`，`src/kvopt/continuum/snapshots.py:153`）。一个 Entry 关联一组 Block（`block_ids`）。**Entry 是 unpin / pressure release 的决策对象，不是物理所有权单位。** |
| **逻辑前缀** *Logical Prefix* | prefix | 一个程序/会话内按 token 顺序连续的历史段。多个逻辑前缀可能映射到**同一个物理 Block**（前缀共享）。逻辑前缀边界由内容哈希决定，不由 Entry 边界决定。 |
| **物理块** *Physical Block* | Block | 显存中固定大小的缓存存储单元，是 **APC 逐出与复用的实际粒度**。物理块可被多个逻辑前缀共享；`ref_cnt` 记录活跃引用数。 |
| **解除保护 / 释放保护** *Unpin / Unprotect* | unpin | 把某个 Entry 的 `protected` 状态置为假，使其关联 Block **获得被回收的资格**。这是**逻辑层操作，不移动任何数据、不释放任何显存**。当前实现是 Entry 级布尔量，**无法只释放一个 Entry 的尾部而保留其浅层共享前缀**——这正是 Entry Idea 4 要改变的对象。 |
| **驱逐资格** *Eligibility* | Tier 1 / Tier 2 | 一个 Block 当前是否可被选为 victim。代码中 `EligibilityTier` 分两级（`src/kvopt/continuum/selection.py:50`）：**Tier 1** = 任何压力释放之前就已可回收（未哈希块、保护已过期的块）；**Tier 2** = 由某次压力释放**新创造**的可回收性。 eligibility 是候选资格，不是"已被选中"。 |
| **压力释放** *Pressure Release* | pressure release | 内存压力下按顺序释放若干 Entry 的保护，直到获得资格的 Block 数达到容量目标。代码：`RetentionAwareSelectionCoordinator.prepare()`（`src/kvopt/continuum/pressure.py:54`）。**注意循环终止条件是"资格数达标"，不是"这些 Block 已被移除"。** |
| **受害者选择** *Victim Selection* | victim selection | 在获得资格的候选 Block 中，决定最终移除哪些物理块。这是**物理层决策**。运行时路径见 `src/kvopt/runtime/vllm/adapter.py` 与 `src/kvopt/costaware/a2_native.py:538`。 |
| **驱逐** *Eviction* | eviction | 真正把物理 Block 从 GPU 缓存中移除的操作。**只有 victim selection 选中并被执行才发生驱逐。** unpin 只创造可能性。 |
| **保留** *Retention* | retention | 在 TTL 内保持某 Entry 的 KV 缓存不被普通逐出路径回收。Continuum 的核心机制；本项目以"项目独立保护表 + 驱逐候选过滤"适配，因为 vLLM 0.27.1 无原生 pin API。 |

**一句话口诀**：unpin 改**资格**，victim selection 选**对象**，eviction 才**移除**。三者不可互换，也不互相蕴含。

## 2. 实验臂（按决策层区分，不可混用）

| 术语 | Entry forced release | Physical block victim selection |
| --- | --- | --- |
| **A0** | 冻结的 Continuum 风格确定性基线 | 现有 eligibility 下的 native LRU |
| **A1** | cost-aware Entry 级选择 | 与 A0 相同的 Block 层基线 |
| **A2** | A0 的 Entry 级释放 | cost-aware Block 级 selector |

`A2` **不是** A1+A2 的联合策略。A1 与 A0 的差异不能单独建立 A1 的 q/λ/pair-lookahead 信号的独立价值。任何未来正式结论都必须包含 **`Sufficient-first + earliest-deadline`** 这一强比较对象。

**冻结 A0 顺序** *Frozen A0 ordering*：代码注释对 `_release_sort_key()` 的称呼（`src/kvopt/continuum/pressure.py:325`），返回 `(entry.deadline_timestamp, native_key, key.sort_key)`；`native_key` 是该 Entry 释放后新获得资格的 Block 中最小的 `native_lru_rank`。与 `docs/baseline-freeze.md` §8 冻结的 "earliest retention deadline first → native LRU rank as tie-breaker" 对应。**不得**把它描述为随手实现的启发式。

## 3. 基础架构与显存管理

| 术语（中文/英文） | 缩写/标识符 | 标准定义与系统作用 |
| --- | --- | --- |
| **KV 缓存** *KV Cache* | KV Cache | 自回归推理中缓存的历史 token 的 Key/Value 张量，用于避免重复计算；显存占用随上下文长度与并发数近似线性增长，是本项目研究的对象。 |
| **预填充** *Prefill* | Prefill | 对输入历史做一次完整前向计算的阶段，计算密集；缓存块被逐出后再次被需要时必须重做，因此是"重算成本"的主要来源。 |
| **物理块 / 逻辑块** *Physical / Logical Block* | Block | 物理块是显存中固定大小的缓存存储单元；逻辑块是请求上下文中的缓存段，两者通过块表映射。**物理块是本项目的驱逐决策粒度**；Entry 是保护释放的决策粒度。 |
| **分页注意力** *PagedAttention* | PagedAttention | vLLM 提出的机制，把逻辑连续的 KV 缓存切成固定大小物理块非连续存放，解决碎片问题；它是驱逐策略的运行基础，本项目不修改该机制本身。 |
| **自动前缀缓存** *Automatic Prefix Caching* | APC | 按 token 内容及前缀计算哈希实现跨请求块共享（如共享系统提示词）的机制；共享前缀正是"重算昂贵"块的典型来源。 |
| **引用计数** *Reference Count* | ref_cnt | 记录当前有多少活跃请求正在引用某物理块；`ref_cnt > 0` 的块不得被驱逐，这是所有候选策略（含基线）必须遵守的硬约束。**注意：`ref_cnt` 存在于运行时候选层** `EvictionCandidate`（`src/kvopt/runtime/vllm/types.py:7`，由 vLLM 块快照经 `VLLMEvictionBridge` 填充）；仓库内的 `KVCacheManager` **没有**引用计数语义，且 `free()` 一次释放某请求全部 Block，不得用作共享语义的参照。 |
| **驱逐候选** *Eviction Candidate* | — | 满足驱逐前提（如 `ref_cnt` 归零、获得 eligibility）的块的集合。运行时契约为 `EvictionCandidate` + `EvictionContext`。 |
| **原生 LRU 秩** *Native LRU Rank* | `native_lru_rank` / `lru_rank` | Block 在原生 free queue 中的位置。真实 A0 路径的排序键是 `(eligibility_tier, native_lru_rank)`（`src/kvopt/continuum/selection.py:100`）；离线辅助函数 `native_selection()`（`a2_geometry.py:264`）与 `native_lru_order()` 只按 `native_rank` 排序、**不含 tier 约束**，是内部参照而非 A0 基线。 |

## 4. 驱逐策略与算法

| 术语（中文/英文） | 缩写/标识符 | 标准定义与系统作用 |
| --- | --- | --- |
| **最近最少使用** *Least Recently Used* | **LRU** | 按最后访问时间选择逐出候选的策略；A0 的 Block 层基线是"现有 eligibility 下的 native LRU"。该策略不直接估计不同候选的重算时间。 |
| **成本感知 Block 选择** *Cost-Aware Block Selection* | — | **A2 实验臂 / Block Idea 1–2 的研究对象**，不是已交付的方法：在获得资格的候选 Block 中按代理加权损失排序。运行时入口 `A2NativeBlockAdapter.select_victims()`（`a2_native.py:538`）；离线入口 `A2BlockSelector.select()`（`a2_selector.py:327`）。**两条路径输入不同，结果不能互推。** 具体评分函数与阈值尚未冻结。 |
| **成本感知 Entry 释放** *Cost-Aware Entry Release* | — | **A1 实验臂 / Entry Idea 3 的研究对象**。A1 的排序键为 `(expected_recompute, deadline, identity)`（`a1_entry.py:163`），分支阶梯为 single_step / per_unit / pair_lookahead / deadline_fallback。 |
| **Sufficient-first + earliest-deadline** | — | 必需的强比较对象：先选"单独释放即可满足容量需求"的 Entry，再按最早 deadline。已记录复现 **54/54** 个 A1 Gate 2 强制释放选择。 |
| **自适应替换缓存** *Adaptive Replacement Cache* | **ARC** | 以新近度、频率双队列加幽灵缓存反馈自适应分配空间的替换算法；本项目仅作对比参照，不复现。 |
| **随机叶子驱逐** *Randomized Leaf Token Eviction* | **RLT** | 在未标记叶子 token 中随机选择逐出对象的算法；本项目仅作理论参照，不复现。 |
| **工作流感知 LRU** *Workflow-Aware LRU* | **WA-LRU** | SAGA 提出的驱逐排序机制，结合 AEG 预测的重用概率、新近度和缓存大小；需要工作流信息，不直接按候选块重算时间排序。本项目不接入。 |
| **虚假驱逐** *False Eviction* | — | 缓存仅因暂时无人访问（如 Agent 等待工具返回）即被逐出、随后又立即被需要的现象；是 retention 类机制的核心失败模式。 |
| **软留存 / 硬锁定** *Soft Retention / Hard Pinning* | — | 软留存指带时限或优先级、在资源紧张时可解除的保留；硬锁定指无条件禁止驱逐，可能造成显存耗尽。vLLM 0.27.1 无原生 pin API，故冻结适配是"项目独立保护表 + 驱逐候选过滤"：受保护块仍留在原生 free queue 中并保留 APC 哈希元数据，**禁止**用抬高 `ref_cnt`、移入隐藏池或复制 BlockPool 记账来模拟 pin。见 `docs/baseline-freeze.md` §6。 |
| **强制首释放** *Forced First Release* | `diagnostic_first_release_program_id` | `prepare()` 的参数；设置后**第一次压力释放被强制指定到该 program，完全绕过 `_release_sort_key()`**（`pressure.py:116-143`）。这类运行衡量的是"某一次特定释放的效果"，不是"排序的效果"；排序比较中必须排除或单独分层报告。 |

## 5. 成本与信号模型

| 术语（中文/英文） | 缩写/标识符 | 标准定义与系统作用 |
| --- | --- | --- |
| **生存时间** *Time-to-Live* | **TTL** | 为受保护 Entry 设置的保留时长。Continuum 在 TTL 内保留对应程序/会话前缀的 KV 缓存，到期后解除保护；内存不足时还可提前解除部分保护。项目实现必须以**动态 TTL**复现，固定 TTL 不可接受；保护以 `(program_id, prefix_id)` 为键，`request_id` 不得当作程序身份。见 `docs/baseline-freeze.md` §1、§3、§4。 |
| **复用代理** *Reuse Proxy* | `q` / `reuse_proxy` | `sigmoid((deadline − t)/tau)`（`a2_geometry.py:453`），与 A1 共用。**这是排序代理，不是校准过的复用概率**：其量级不是测得的复用概率或复用次数，只有排序性有第一性原理依据。`tau` 按战役冻结，任何用它得出的结果都必须同时报告 `tau`。 |
| **重算成本** *Recomputation Cost* | — | 缓存未命中后重新预填充所需的时间与计算开销。**区分三个不同的时间量**：(1) 工具调用到工具返回的时间；(2) 一轮结束到下一请求到达的时间；(3) 在请求尚未到达的条件下剩余时间。三者是不同随机变量，不可混用。 |
| **记忆度** *Memoryfulness* | **eta** | Continuum TTL 目标函数中刻画程序剩余轮次可预测性的因子。Phase 1B 冻结定义为 `eta = -PearsonCorr(k, N-k)`，样本取自已完成程序的每个非终止轮；允许为负值且**不得裁剪到 [0,1]**；无法计算时回退 `eta = 1`（记录为 `source = APPROXIMATED`，原因码 `reason = FULLY_MEMORYFUL_COLD_START`）。见 `docs/archive/phase1b-continuum/phase1b-continuum-implementation-decisions.md` §1.6。 |
| **外部工具时长历史** *External Tool Duration History* | `ExternalToolDurationHistory` | 在 `history.py:52` 定义、`runtime.py:332` 写入。**当前状态：只写不读——全仓库没有任何代码调用其 `global_samples()` 或 `samples_for_tool()`。** 不得把它描述为已被驱逐算法使用；使用前必须先实现并测试消费者。 |
| **右删失** *Right Censoring* | — | trace 因任务步数上限（如 S50/S100）或采集终止而被截断的现象。把删失记录当作完整观测会污染间隔分布估计。 |
| **成本异构性** *Cost Heterogeneity* | — | 不同缓存块被逐出后的重算代价差异显著这一性质（如万级 token 共享前缀与几十 token 对话尾部）。*这是动机层面的痛点陈述，不是已证实的收益来源。* |
| **逐出代价 / 驱逐损失** *Eviction Loss* | — | 逐出某 Block 带来的预期损失。**具体评分函数尚未冻结**，任何形式都保持 hypothesis 定位。 |

## 6. 智能体工作负载相关

| 术语（中文/英文） | 缩写/标识符 | 标准定义与系统作用 |
| --- | --- | --- |
| **智能体工作负载** *Agentic Workload* | — | 以"思考—行动—观察"循环为特征的多轮任务负载（如编程、浏览器智能体）。 |
| **工具调用** *Tool Call* | — | Agent 请求外部工具执行并等待返回的动作；执行期间 LLM 推理暂停，其 KV 缓存暂时无人访问，是虚假驱逐的高发场景。 |
| **挂起期** *Idle Pause* | — | 工具调用期间模型推理暂停的时间窗；保留类机制（Continuum/SAGA）正是针对该窗口设计。 |
| **多轮对话** *Multi-Turn Conversation* | — | 同一会话内多次请求共享历史上下文的负载形态；会话越长前缀越贵，误逐一次的损失越大。 |
| **智能体执行图** *Agent Execution Graph* | **AEG** | SAGA 用于预测未来复用概率的工作流结构图。本项目拟不接入此类工作流图。 |
| **Agent Step Graph / steps-to-execution** | ASG | KVFlow 中表示 agent 执行计划的结构，及 agent 距未来被激活的步数。**依赖工作流结构信息**，不能假设其在本项目真实驱逐时刻可用。 |

## 7. 性能指标与证据分层

| 术语（中文/英文） | 缩写/标识符 | 标准定义与系统作用 |
| --- | --- | --- |
| **首词延迟** *Time To First Token* | **TTFT** | 请求提交到首个输出 token 返回的时间；直接受缓存命中与重算开销影响。 |
| **缓存命中率** *Cache Hit Rate* | — | 请求的输入 token 中成功复用现有缓存、免于重算的比例。 |
| **吞吐量** *Throughput* | — | 单位时间内完成的请求（或 token）数。 |
| **每 token 输出耗时** *Time Per Output Token* | **TPOT** | 解码阶段平均每生成一个输出 token 的耗时；用于排查驱逐策略对解码路径的副作用。 |
| **端到端延迟 / 完成时间** *End-to-End Latency / JCT* | JCT | 单个请求（或整个多轮任务）从提交到完成的总耗时；多轮场景下关注任务级完成时间。 |
| **重算量** *Recomputed Tokens* | — | 因缓存未命中而重新预填充的 token 总量。 |
| **证据分层** *Evidence Tiers* | `N` `E` `C` `R` `W` `S` | 对具有完整原生 hash/APC 证据的请求：`N` = 原生 prompt token，`E` = 可复用的 eligible 原生前缀 token，`C` = 原生已缓存前缀 token；强制 `0 ≤ C ≤ E ≤ N`，并分别报告 `R = E − C`（eligible 前缀重算）、`W = N − C`（实际 prefill 工作量）、`S = N − E`（真正新增后缀），且 `W = R + S`。**逻辑释放、物理 hashed 驱逐、后续 APC 命中、请求级重算是不同层次的观测，不可互相推断。** |
| **策略决策开销** *Policy Decision Overhead* | — | 驱逐选择本身消耗的额外时间与内存（如排序、元数据维护）。 |
| **消融实验** *Ablation* | — | 逐一关闭信号分量以定位收益来源；尤其是验证中间信号在 **conditional on the deadline** 之下的增量价值。 |

## 8. 证据等级措辞规范

| 等级 | 可用措辞 | 示例 |
| --- | --- | --- |
| **已实现 / 已验证** | "已实现并通过测试/真实运行时验证" | Phase 1B Continuum 风格基线已集成并真实运行时验证 |
| **论文报告** | "论文报告…（条件：…）" | Continuum 摘要报告平均 JCT 改善 over 8× |
| **已观察到的项目结果** | "在有界评估中观察到…（范围：…）" | A2 有界评估 0 better / 3 worse / 33 tied（36 draws） |
| **研究假设 / 设计提案** | "假设…"、"待检验…"、"尚未冻结" | H1–H4；partial-tail unpin 规则 |
| **尚不可判断** | "未建立"、"NOT_ESTABLISHED"、"数据不足" | 单次物理驱逐的因果归因 |

**禁止**在缺少项目证据时使用"证明优于 LRU""显著提高性能""解决了复用问题"等措辞。
