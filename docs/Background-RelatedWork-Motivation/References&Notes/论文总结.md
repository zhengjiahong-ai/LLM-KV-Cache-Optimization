# 论文总结：KV Cache 管理、保留与成本感知决策

本文主体按论文记录机制、评估条件和适用边界。作者与版本见[文献索引](参考文献/文献索引.md)，横向比较见[对比笔记](对比笔记.md)。旧版逐篇精读的 11 项统一模板、关键实验细节和 PPT 图表索引已整理至[论文精读附录](论文精读附录.md)。项目采用 vLLM 0.27.1 GPU APC，以 Phase 1B 的 Continuum-style adaptation 为系统基础。本文中的论文结果均为作者报告，项目贡献与实验边界见[研究定位](../../research-motivation-and-contributions.md)。

## 1. PagedAttention / vLLM：块化管理与前缀共享

连续预分配会留下预留空间和碎片，还会重复保存相同 KV。PagedAttention 将序列的逻辑 KV 块通过 block table 映射到非连续的物理 Block，按需分配，并支持并行采样、beam search 等场景中的共享与 Copy-on-Write。决策依据是序列长度、块表和共享状态，粒度为物理 Block，无需 Agent 工作流信息。论文 §4.5 的 all-or-nothing preemption 与 CPU swap/recompute 针对运行序列的恢复。

**论文评估。** Figure 2 在 §6.2 的 basic sampling 实验中比较 Orca 连续分配方案，实际 token states 只占其 KV 内存的 20.4%–38.2%。§6.2 使用 ShareGPT 与 Alpaca 的长度分布，测试 OPT 系列和不同 GPU 配置。Figure 5 适合说明逻辑块与物理块的映射。

**项目关联。** 分页与共享提供 Block 层实验载体。历史序列抢占机制与当前 vLLM 0.27.1 GPU APC 回收无活跃引用的缓存块是不同路径，具体版本边界见 [vLLM 参考文档](参考文献/关于vLLM的参考文档与网址.md)。

## 2. ARC：用访问历史调整缓存分配

文档 QA 的热点和多轮对话的时间局部性可能共用同一个缓存。该工作把 ARC 应用于 vLLM 的固定大小 KV Block，用 T1/T2 分别记录一次访问和重复访问的驻留项，用 B1/B2 保存已驱逐项的元数据。Ghost hit 反馈调整两类队列的容量目标，重复访问可将项晋升至频繁队列。该策略在 Block 替换层使用 recency、重复访问与 ghost hit，无需工具或会话生命周期信息。Figure 2 可用于解释双队列与 ghost 反馈。

**论文评估。** §4 使用 Qwen3-14B 和单张 H100 PCIe 80 GB，在 QuALITY/WikiQA 文档 QA 与真实多轮对话 trace 上比较 LRU、固定双队列 DBL 和 ARC。以 §4.1 的文档 QA 结果为例，QuALITY 容量扫描中，作者报告相对 LRU 的命中率改善为 1.2%–10.8%，平均 TTFT 下降 2.0%–12.6%。对话负载的效果较小，容量和访问分布会影响比较结果。

**项目关联。** ARC 提供 Block 替换的访问历史参照。Ghost 反馈调节空间配比，无法直接提供某个候选被驱逐后的 prefill 重算代价，也不改变逻辑 Entry 的保护。

## 3. RLT / LBGR：前缀树替换与多 worker 路由

有限缓存下，到达顺序会影响前缀树叶子上的命中。RLT 在压力下从未标记的叶子 token 中随机选 victim，标记由访问过程更新。论文 §3.2、§4.1 给出其模型内的最坏情况竞争比分析，Leaf-LRU 为 O(n) 量级，RLT 为 O(log n) 量级。这里的替换对象是 RadixAttention 的叶子 token。

LBGR 解决另一层问题，即在多个 worker 之间权衡前缀亲和与排队负载。它用已有的服务与排队观测学习请求时延，作用对象是请求的路由目标。该时延模型并未参与 RLT 的随机替换。

**论文评估。** §5 在 SGLang 以 Leaf-LRU 为替换对照，并交叉比较随机、轮转、cache-aware 与 LBGR 路由。负载包括 Generated Shared Prefix、ShareGPT/UltraChat 和 Loogle，覆盖随机到达与最坏情况轮转到达。Llama-3.1-8B-Instruct 在 L40 上运行，Llama-3.1-70B-Instruct 与 Mixtral 8×7B 在 H200 上运行。Figure 4 中，在 Llama-3.1-8B-Instruct 的 Loogle 轮转到达实验里，作者报告 LBGR+RLT 优于论文内其他组合，比较包含路由与缓存替换。

**项目关联。** 固定路由后再比较替换策略的做法有助于区分组件效应。理论竞争比和多 worker 时延依赖论文的模型、前缀树和到达条件，不能换算为本项目 Native Block 层的收益。

## 4. Continuum：程序感知的 TTL、保护与调度

多轮 Agent 等待工具期间，KV 可能被普通回收路径淘汰。下一轮返回后既要重算，也可能重新排队。Continuum 将请求关联到 program，在工具调用间隔内用 TTL 保留该 program 的 KV，并按抢占状态、TTL 状态和程序到达顺序协调调度。主要决策对象是请求的 KV 保留和 program 的调度顺序。

**TTL 与压力处理。** §4.1–4.2 用经验 CDF 估计工具在候选 TTL 内返回的概率。在候选集合 `{0} ∪ 已观测间隔` 上枚举，最大化 `P(τ,f) × (Tη + PrefillReload) − τ`。T 表示排队等待，η 反映已执行轮次对剩余轮次的预测性，PrefillReload 来自重算或载入代价。§5.1 用同 program 的服务端请求间隔估计工具耗时。§5.2 处理 TTL 到期、程序结束和容量不足，死锁预防按较晚的 program 到达时间选择待解除保护的请求。Figure 7 和 Algorithm 1 可用于说明 TTL 与调度如何协作。

**论文评估。** 仓库 PDF 为 arXiv v6。§6 区分 SWE-Bench、BFCL、OpenHands 的重放和真实 SWE-agent 运行。§6.1 的重放配置包括 Llama-3.1-8B/70B、Gemma-3-12B、A100/H100/B200，以及 vanilla vLLM 0.10.2 等对照。§6.2 在 Llama-3.1-8B 重放讨论中报告平均响应时间相对 vanilla vLLM 最多约改善 2×。摘要的 over 8× 与 §1 的 up to 8.18× 属于较宽的论文系统结果，§1 将后者联系到 Tensormesh 的真实 SWE-agent 测试，§6.2 描述了 H100 上的 500 个 SWE-Bench Verified 任务。该最大值对应的具体负载点与比较对象未逐项标定。§6.4 另有 8×H100 上的 GLM-4.5-fp8 rollout microbenchmark。

**项目关联。** Phase 1B 从该设计适配 program/session identity、请求间隔历史、Dynamic TTL、软保护和窄范围 admission order。项目使用独立保护表与候选过滤，外部工具执行时长与服务端请求间隔分开记录。A0 的项目侧 Entry Release 顺序冻结为 `(entry.deadline_timestamp, min native_lru_rank among Blocks newly eligible after releasing that Entry, deterministic Entry identity)`；若没有新增资格 Block，第二键按正无穷处理。它不同于论文 §5.2 按 latest program arrival time 进行死锁预防的规则；A0 的物理 Block victim selection 仍为 Native LRU。Phase 3 固定 Native scheduler，分别比较 Entry Release 与 Block Victim Selection。见[基线冻结](../../baseline-freeze.md)和[实现说明](../../continuum-baseline-implementation.md)。

## 5. SAGA：工作流级的分布式调度与缓存管理

SAGA 将 Agent 工作流作为调度单元。Agent Execution Graph（AEG）来自框架提示或历史 trace 推断，用来预测后续复用。系统把工具类型的历史时长分位数与显存压力结合调整 TTL，WA-LRU 按预测复用概率、新近度和缓存大小排序。分布式层另有 session-affinity batching、work stealing 与 Agent Fair Share。TTL、替换排序和集群调度使用不同决策对象。

**论文评估。** v2 Table 2 用生产 trace 对照 Bélády 离线最优，竞争比越低越好。三个旧笔记常引用的数字跨列，SWE-bench 应比较 2.84、1.97、1.31。

| Table 2 策略 | SWE-bench | WebArena | Mean |
| --- | ---: | ---: | ---: |
| Standard LRU | 2.84 | 2.12 | 2.48 |
| LRU + Prefix（vLLM v0.5） | 1.97 | 1.74 | 1.86 |
| WA-LRU | 1.31 | 1.28 | 1.30 |

§9.1–9.2 的系统评估采用 64 张 A100-80GB 和 Llama-3-70B-Instruct（TP=4）。SWE-bench/WebArena 按相同 Poisson 到达计划重放（约 8 tasks/min，单租户，10 次重复）。Table 3 中完整 SAGA 相对 vLLM v0.15.1 + APC + affinity routing 的任务完成时间比分别为 1.73× 和 1.55×。Figure 1 的另一组诊断在 32 张 A100 上跑 SWE-bench，作者报告 vLLM v0.6.0 有 38% 执行时间用于重建 KV，条件与 Table 3 不同。

**项目关联。** SAGA 说明工作流信息可同时作用于 TTL、替换和调度。AEG 接入、分布式路由和论文的联合系统结果均超出当前 Phase 3 的组件比较。Table 2 的竞争比也不是端到端时延比。

## 6. KVFlow：按工作流距离管理 radix tree 前缀

固定 Agent 提示词可能在多次调用间共享。KVFlow 在 SGLang v0.4.4 上用 Agent Step Graph（ASG）表达依赖关系，把离下一次执行的步数（steps-to-execution）传给缓存管理。§3.1 **Workflow-Aware Eviction Policy** 在 KV node 层传播优先级，共享节点取较小的 steps-to-execution，降低其驱逐优先级。§3.2 **Overlapped KV Prefetching** 将预计下一步需要的 KV 从 CPU 异步预取到 GPU，并用状态感知调度重叠传输和计算。Figure 3 将图上的步数与缓存树节点关联起来。

**论文评估。** §4.1 的十 Agent 顺序工作流中，Llama-3.1-8B / A10G 24 GB 在固定提示、动态后缀、输出为 8192/32/32 token 的设置下，相对 SGLang + HiCache 提速 1.83×。§4.2 的独立并发工作流在 Qwen2.5-32B / H100 80 GB 上相对 reactive HiCache 最高提速 2.19×。作者还用 PEER 模板和 Financial QA 做工作流模拟。

**项目关联。** ASG 提供与工具间隔统计不同的前视信号。radix node、CPU 层缓存和预取会共同影响端到端结果，不能用这些倍数估计项目的 GPU APC Block selector 收益。

## 7. CacheWise：用工具上下文预测复用并安排准入

CATraces 的 coding Agent 会话中，LLM 与工具交替，长前缀多次被提交。§5.1 **Prefix-aware Request Scheduling** 优先准入已有较大缓存前缀的等待请求，降低新请求物化 KV 的压力。§5.2 **Predictive KVCache Eviction** 按工具类型、参数及已经等待的时间估计剩余时长，优先逐出预计最晚再次使用的会话中无引用的 Block。估计以工具仍在运行为条件，并用历史样本和参数文本聚类（TF-IDF、KMeans）处理同名工具的耗时差异。该机制依赖工具元数据覆盖和训练分布。

**论文评估。** §6.1 确定性重放 CATraces，80% 会话离线训练，剩余会话用于评估。后端为 vLLM 原型，模型是 Qwen2.5-Coder-32B-Instruct，2×H200（TP=2），chunked prefill 上限 512 token。对照为 vLLM Block LRU + FCFS 和 InferCept 的 moving-average 策略。会话完成时间按 §6.1 定义为各轮 LLM 时延之和，排除工具执行时间。

| 对比 | 作者报告的会话完成时间比 |
| --- | --- |
| 完整 CacheWise 对 vLLM / InferCept（§6.2，N > 10 个并发会话） | 约 2.7×–3.5× |
| 加入预测式驱逐，对照已启用 prefix-aware scheduling（§6.3，Figure 15） | 约 1.7×–2× |
| 单独加入 prefix-aware scheduling（§6.3，Figure 16） | N=30 时约 1.8×–2.35×，N=40 时约 1.85×–2.66× |

**项目关联。** 端到端结果包含准入与驱逐效应。工具特征能否在本项目的 Block 决策时可得、能否补充 TTL deadline，需要独立验证。论文没有直接对比 SGLang，亦未评估本项目的 Entry Release。

## 8. When Fancy Eviction Fails：以 LRU 检验复杂替换的增量价值

论文用 FreeInference 与 Chutes 生产 trace 评估前缀缓存替换，合计约 202 亿 processed tokens。§3.2 比较 14 种在线算法，包括 LRU、ARC、S3-FIFO、LIRS、LFU、LRB 和 Workload-aware 等。Bélády 使用未来访问信息，是单列的离线参照。容量扫描区分每副本 HBM（24–120 GiB）和全局 DRAM/SSD pool（0.25–12 TiB）。多数复杂策略在主 trace 上相对 LRU 收益有限，作者用活跃会话的时间局部性解释该现象。

**条件与反例。** §4.6/Figure 11 的 Qwen To-B trace 在 24 GiB 下，S3-FIFO 与 ARC 的 block hit ratio 为 0.491，LRU 为 0.403。§5 分别研究 quick demotion、compute-aware partial-node eviction 和按容量选择 block/session 粒度。Figure 13 在 H200、48 GiB 上重放 10,000 条 FreeInference 请求，分别测 TTFT 和 prefill throughput，显示部分节点与逐块替换的碎片化后果可能不同。

**项目关联。** 论文的 LRU 是其 trace 评估中的参照，结果支持本项目保留 Native LRU 和控制候选路径。容量、对象粒度与重算代价模型会改变结论。partial-node eviction 发生在缓存替换层，项目的 partial-tail Entry unpinning 则是未来的保护粒度问题。
