## 1. PagedAttention / vLLM —— 背景与实验载体

> 文献：*Efficient Memory Management for Large Language Model Serving with PagedAttention*

### 1.1 核心机制/算法

- **问题量化**：传统系统把 KV 缓存放在连续内存中，产生严重的内部碎片（预分配过大）与外部碎片，实测 KV 缓存内存利用率低至 **20.4%**，直接限制了批大小与吞吐。
- **PagedAttention**：借鉴操作系统虚拟内存分页，把 KV 缓存切成固定大小的块，允许非连续存放、按需动态增长，几乎消除碎片；块级管理天然支持跨序列共享（并行采样、Beam Search、共享前缀），配合写时复制（Copy-on-Write）进一步省内存。
- **驱逐与恢复**：由于自回归推理要求一个序列的所有 KV 块同时在场，vLLM 采用 **"全有或全无"** 的驱逐策略；恢复时提供 **交换到 CPU 内存** 与 **重计算** 两种方案。

### 1.2 基线复现价值

- **不需要复现**该论文本身。它是所有实验的运行载体（后端为 vLLM 0.27.1 + GPU APC）。
- 需要继承的设定是块级（固定大小块）的缓存管理粒度。A0 的 Block 层基线是"现有 eligibility 下的 native LRU"，采用 vLLM 原生前缀缓存的逐出语义（vLLM v0.6.0 文档记载：只考虑 `ref_cnt = 0` 的块，多候选时优先最久未使用，时间相同时优先最长前缀末端；见 [`参考文献/关于vLLM的参考文档与网址.md`](参考文献/关于vLLM的参考文档与网址.md)），**不**将其表述为 PagedAttention 论文的默认逐出实现。

### 1.3 对本项目的启发

- **正面**：分页使"以块为单位做驱逐决策"成为可能，Block 层研究天然作用在块/前缀粒度上。
- **局限**：该论文讨论的"全有或全无"恢复方式以序列为单位，未给出按候选块重算损失排序的策略。项目若改为块级排序，需要在实现中确认不破坏后端的块表和引用计数约束。
- **参考**：交换 vs. 重计算的权衡分析，可作为定义"重算成本"信号时的依据。

## 2. Recency/Frequency Adaptive KV Caching（ARC）—— 自适应但仍"成本盲目"

> 文献：*Recency/Frequency Adaptive KV Caching for Large Language Model Serving*

### 2.1 核心机制/算法

- **动机**：LRU 只看新近度，无法应对多样化负载；不相关的工作负载会互相冲刷缓存。
- **机制**：把操作系统中的 **自适应替换缓存（ARC）** 引入 vLLM：
  - **双队列**：低频队列（L1，只访问过一次）与高频队列（L2，访问多次），L1 中被再次命中的项晋升到 L2；
  - **幽灵缓存（Ghost Cache）**：只记录被逐出块的元数据，用于估计"如果缓存更大能否命中"，其命中情况作为反馈信号，动态调整 L1/L2 的物理空间配比。

### 2.2 基线复现价值

- **不复现为基线**。它的价值是作为 Related Work 中的"中间档位"：相对 LRU 增加了频率维度与自适应空间配比，但其信号仍不回答逐出代价。
- 其实验设置可作为参考：对比纯 LRU，使用 QuALITY、WikiQA、合成 Zipf 负载和多轮对话 trace，并报告命中率与 TTFT。最终数据集和指标仍以 `docs/experiment-plan.md` 为准。

### 2.3 对本项目的启发

- **可借鉴**：
  - 频率是一个独立于新近度的有效复用信号，Block Idea 2 可把"近期复用历史"纳入候选信号；
  - 评估函数不应是静态的，应随负载动态调整——呼应"在线动态感知"的定位；
  - 幽灵缓存提示我们：即使一个块当前不活跃，也可以低成本地保留它的元数据来估计潜在收益。
- **局限（即本项目要检验的空白）**：
  - **不感知逐出代价**：ARC 只关心"会不会再被访问"，不关心"被逐出后再访问要花多大代价"；
  - **不感知异构代价**：不同长度、不同位置的块被一视同仁；
  - **自适应范围有限**：它调的是新近度/频率的配比，而不是对实时系统状态（显存压力、排队）的响应；
  - 实验中 KV 块固定为 16 token，未考虑不同内存足迹下的价值最大化。

## 3. Randomization-Boosts-KV-Caching（RLT + LBGR）：理论参照

> 文献：*Randomization Boosts KV Caching: Learning Balances Query Load — A Joint Perspective*

### 3.1 核心机制/算法

- **对 LRU 的批判（可直接引用为动机素材）**：
  - 对动态在线查询脆弱，容易逐出后续就要用的 KV，导致未命中与延迟上升；
  - 多 LLM 场景下，缓存亲和与全局负载均衡目标冲突，LRU 表现不稳；
  - **理论上**：前缀共享结构下 LRU 最坏情况竞争比退化为 \(O(n)\)。
- **RLT（Randomized Leaf Token eviction）**：缓存满时，从**未标记的叶子 token 中随机选一个逐出**。随机性打破了对查询到达顺序的依赖，最坏竞争比改善到 \(O(\log n)\)。
- **LBGR（学习型贪心路由）**：用在线学习估计端到端延迟（服务时间 + 队列负载 + 残差校正）来路由请求。

### 3.2 基线复现价值

- **不复现为基线**（超出项目范围）。它说明在论文给定的前缀共享和到达顺序条件下，随机化也能改善 LRU；实验讨论中应说明本项目与其比较的是决策信号，而非直接比较性能。
- **指标体系直接复用**：命中率、吞吐、延迟与 TTFT，以及给出驱逐与路由的**运行时开销分解**——这正是我们实验计划中"优化开销"一节的范本。

### 3.3 对本项目的启发

- **可借鉴**：
  - "在随机/简单选择之前先排除高价值项"的思路，可与成本排序互补；
  - LBGR 的延迟估计公式（服务时间 + 队列负载 + 残差校正）提示：驱逐侧的估计也可以是**多维信号的在线估计**，而非固定公式；
  - 竞争比分析为评价本项目策略提供了理论工具（至少可以引用）。
- **局限（即本项目要检验的空白）**：
  - RLT 的逐出决策是**随机的**，完全不评估单个块的"价值"或"逐出代价"；
  - 成本估计只发生在**路由**环节（对整个查询），而不是**驱逐**环节（对单个块）；
  - 未利用共享度、访问频率等更细的复用信号；内存足迹也不在决策内；
  - 其成本模型聚焦时间维度，没有刻画异构的逐出代价（如长前缀重算对 TTFT 的破坏）。

## 4. Continuum —— 必须复现的强基线（TTL / retention policy）

> 文献：*Continuum: Efficient and Robust Multi-Turn LLM Agent Scheduling with KV Cache Time-to-Live*

### 4.1 核心机制/算法

- **问题**：Agent 工作流中工具调用会让 LLM 请求暂停。传统管理下，暂停期间 KV 缓存可能被驱逐（返回后要重新做昂贵的预填充），同时 GPU 资源被其他请求占用（返回后还要再排队，即"调度气泡"）。
- **核心思想**：**工具感知的 TTL + 程序级调度**。
  - 请求完成但程序未结束时，软保护对应程序 / 会话前缀条目，将其 KV 缓存保留在 GPU 内存；
  - 为每个受保护条目设置 **TTL 过期时间**，防止无限占用；
  - 调度器按「抢占请求 > 受保护程序的后续请求 > 程序级 FCFS」定优先级。
- **TTL 计算依据**：服务端请求间隔历史（server_inter_request_gap）记录，结合排队延迟 T、预填充重算开销 PrefillReload 与轮次记忆度因子 eta；外部工具调用时长（external_tool_duration）仅单独记录为诊断与消融元数据，不作为主估计器的分布样本。
- **关键机制细节**：TTL 到期且下一请求未到达则释放；内存不足时选择性解除保护防死锁。

### 4.2 基线复现价值（这是 A0/A1 的来源）

复现范围聚焦其**决策逻辑**，而非整套系统。核心要素：

- **核心算法**：
  1. `CalcTTL` 函数：利用服务端请求间隔历史（server_inter_request_gap）样本集合 \(S[f]\) 构建**经验 CDF**（非参数的阶跃分段函数），在离散候选集 `{0} ∪ 已观测时长` 上暴力枚举，求解式 (2) 的目标 \(\arg\max_\tau\; P(\tau, f)\cdot(T\eta + \mathrm{PrefillReload}(r)) - \tau\)，得到最优 TTL \(\tau^*\)；
  2. 软保护 / 解除保护逻辑：按 `CalcTTL` 结果保留或释放对应程序 / 会话前缀条目的 KV 缓存；
  3. 调度优先级：受保护程序的后续请求优先 + 程序级 FCFS；
  4. 死锁预防：内存压力下选择性解除保护。
- **核心数据结构**：
  - `Pinned_Programs_Map`：`program_id → TTL_timestamp`；
  - `Historical_Tool_Call_Records`：按工具类型（及全局）**保留完整的时长样本集合 \(S[f]\)**，作为在线构建经验 CDF 的原始数据；外部工具调用时长（external_tool_duration）仅单独记录为诊断与消融元数据，不作为主估计器的分布样本。
- **实现注意事项**：正确识别程序 ID 与工具类型、精确测量工具调用间隔、实现软保护 / 解除保护机制、改调度优先级、防死锁。项目侧冻结的 TTL 语义（CDF 构造、候选枚举、冷启动层次等）以 `docs/archive/phase1b-continuum/phase1b-continuum-implementation-decisions.md` §1 为准。
- **边界提醒**（与 `docs/baseline-freeze.md` 一致）：项目实现的是**适配到 vLLM 0.27.1 的 Continuum 风格基线**，因为 vLLM 缺少 Continuum 原生的程序/会话身份、pin API、工具间隔状态与程序级调度原语。该基线**不得被描述为源码级的精确复现**，也不得退化成普通 LRU。复现范围冻结前需书面记录复现了哪个决策机制、与原始系统有哪些运行时假设差异、省略了哪些组件。

### 4.3 对本项目的启发

- **可借鉴**：
  - "保留决策需要量化收益"的思想：保留的收益 = 省下的重算 + 省下的排队，代价 = 占用的显存时间；
  - 在线收集请求间隔统计并更新预测——一种轻量的"在线感知"范式；
  - 其局限即为本项目的研究空间（见下）。
- **与本项目的两层决策的关系**：
  1. Continuum 会在空间不足时解除部分保护以避免死锁，但其主要输出仍是每个程序 / 会话的 TTL，而非对全部可逐出块的统一排序；
  2. TTL 依赖服务端请求间隔历史（server_inter_request_gap）。冷启动、间隔分布变化或长尾都会影响估计质量；
  3. 论文的保留和解除保护以请求的 KV 缓存为单位，不区分同一请求内不同块的重算价值；
  4. **本项目在 Entry 层研究释放顺序与释放粒度，在 Block 层研究受害者选择**；这两个决策点可与 TTL 保留组合，但是独立可检验的研究问题（Entry Idea 3 / Idea 4，Block Idea 1 / Idea 2）。

## 5. SAGA：工作流感知的保留与逐出参照

> 文献：*SAGA: Workflow-Atomic Scheduling for AI Agent Inference on GPU Clusters*

### 5.1 核心机制/算法

- **问题**：传统调度器将每次 LLM 调用视为独立请求。论文在其 SWE-bench 实验中报告（32 张 A100、vLLM v0.6.0、10 次重复），vLLM v0.6.0 有 **38% 的总时间**用于重新生成工具调用期间被丢弃的 KV Cache，GPU 显存利用率平均仅 42%。论文另述，对 32K 上下文、70B 级模型、GQA 的 Agent 会话，KV 缓存为 **2–12 GB/请求**。
- **工具调用感知 TTL**：
  - 基础 TTL 来自特定工具类型的历史延迟（如取 **95% 分位数**）；
  - **显存压力大时按比例缩短 TTL**；设最大上限（如 300 秒）；
  - 内存压力达到高阈值时会触发硬驱逐，TTL 不是无限期保护。
- **WA-LRU（Workflow-Aware LRU）**：使用 AEG 预测的未来复用概率、新近度和缓存大小进行逐出排序。
- **AEG 来源**：论文中可使用编排框架提供的提示，也可由历史请求 trace 进行模式推断。

### 5.2 基线复现价值

- **不复现为基线**。其价值有两点：
  1. 作为 A0 / Baseline 2 的对照设计参考，帮助说明保留时长、内存压力和驱逐排序可以分开设计；
  2. WA-LRU 是信号设计上最接近 Block Idea 2 的相关工作之一。两者的主要区别是，SAGA 使用 AEG 预测复用，而本项目**拟检验**是否能在不接入 AEG 的条件下，仅用本地运行时历史估计复用并改进受害者选择。**这是待检验假设，不是已成立的区别。**

### 5.3 对本项目的启发

- **可借鉴**：
  - **显存压力动态缩放 TTL** 的思路，可作为 Block 层信号中"当前缓存压力"分量的参照实现；
  - "未来复用概率 + 缓存属性"可形成排序分，为设计多信号策略提供参考；
  - 评估指标 **TCT（任务完成时间）、GPU 内存利用率、驱逐竞争比（对照 Bélády 最优）** 值得纳入指标讨论。
- **与本项目的关系**：
  - SAGA 需要 AEG 或相应的 trace 推断，接入和预测误差都是额外条件；
  - WA-LRU 的分数不直接以候选块的逐出代价为输入；
  - 本项目**拟检验**用本地运行时历史改进 Block 受害者选择。该定位需要通过实验验证，而非预设性能结论。

## 6. KVFlow —— Agent Step Graph 驱动的前缀缓存管理

> 文献：Zaifeng Pan, Ajkumar Patel, Zhengding Hu（UC San Diego）、Yipeng Shen（AWS）、Yue Guan（UC San Diego）、Wan-Lu Li（AWS）、Lianhui Qin（UC San Diego）、Yida Wang（AWS）、Yufei Ding（UC San Diego），*KVFlow: Efficient Prefix Caching for Accelerating LLM-Based Multi-Agent Workflows*，arXiv:2507.07400v1，2025-07-10。

### 6.1 核心机制/算法

- **问题**：多智能体工作流中每个 agent 由固定提示初始化，前缀高度重叠；现有系统按 LRU 逐出，导致缓存未命中与换入停顿。
- **Agent Step Graph（ASG）与 steps-to-execution**（论文 §3.1）：把 agent 执行计划抽象为图，每个 agent 赋予一个 `steps-to-execution` 值，估计它距未来被激活还有多少步。同步屏障、条件分支（AND/OR）等结构由图表达。
- **工作流感知的驱逐优先级传播**（论文 §3.2）：按 steps-to-execution 在图上传播驱逐优先级；聚合多 agent 输入的节点取其子节点中**最小（最不可逐出）**的优先级，保证**共享节点只要对任一 agent 在不久的将来有用就被保留**；并发工作流在共享节点上的冲突以最低（最保守）优先级解决。论文摘要明确称其在树状结构中高效管理**共享前缀**。
- **预取与调度**（论文 §3.3、§3.4）：重叠的 KV 预取机制在后台把下一步调度到的 agent 所需张量从 CPU 预取到 GPU；另有状态感知调度。**预取与本项目研究的驱逐是不同问题。**

### 6.2 决策层级、信号与信息需求

| 维度 | KVFlow |
| --- | --- |
| 决策层级 | 驱逐优先级 + 预取 + 调度 |
| 使用的信号 | Agent Step Graph 结构、steps-to-execution、共享前缀关系 |
| 需要的外部信息 | **工作流结构与 agent 依赖/激活关系** |
| 适用场景 | 结构化多智能体工作流（论文用合成与 PEER 风格工作流评估） |

### 6.3 原文结论（论文报告，非本项目结果）

摘要报告：相对带层次化 radix cache 的 SGLang，单一大提示工作流最高 **1.83×** 加速，多并发工作流场景最高 **2.19×** 加速。

### 6.4 对本项目的启发与限制

- **对 Block Idea 1**：提供了一个"何时值得偏离 LRU"的信号族候选——工作流/未来执行距离。但**它依赖工作流执行信息**；本项目在真实驱逐时刻能否获得这类信息必须单独验证，不能默认可用。
- **对 Block Idea 2**：KVFlow 的信号是**结构化、静态/半静态的工作流距离**；Continuum 的信号是**在线观察量**（请求间隔、排队延迟、工具统计）。二者来源不同，不能互相替代，也不必然相关；应作为独立的信号族对照，而非同一思路的变体。
- **限制**：不得把 KVFlow 的论文结果当作本项目的预期收益；不得把其预取机制与本项目的驱逐研究混为一谈。

## 8. When Fancy Eviction Fails —— 对"复杂驱逐更优"的系统性反向证据

> 文献：Yiyu Liu, Minlan Yu, Juncheng Yang（Harvard University），*When Fancy Eviction Fails: Rethinking Cache Replacement For LLM Prefix Reuse*，arXiv:2609.28870v2，2026-10-01。

### 8.1 核心机制/算法

- **问题**：几十年的传统缓存管理技术能否直接迁移到 Agent/对话式 LLM serving？
- **方法**：分析超过 **200 亿 token** 的生产 trace，在**容量受限的 HBM** 与**大内存池**两种机制下评估 **14 种驱逐算法**（含 per-replica HBM 24–120 GiB/GPU 与 0.25–12 TiB 全局内存池的设置）。
- **结构性解释**（论文 §4.2）：前缀复用主要由**活跃会话的稳定节奏**主导，使 recency 成为异常强的预测因子；同时前缀缓存与传统负载存在差异——单轮请求普遍、会话足迹极度倾斜（§4.5 Heavy-Tailed Session Footprints）、miss cost 因注意力计算随 token 深度增长而高度非均匀（§4.4 Position-Dependent Miss Costs）。
- **设计原则**（论文 §5）：以 recency 为基线，加入 **quick demotion**（§5.1，过滤一次性提示）、**compute-aware eviction**（§5.2，优先处理昂贵 miss）、**capacity-adaptive eviction granularity**（§5.3 Block-Level vs. Session-Level Eviction）。

### 8.2 决策层级、信号与信息需求

| 维度 | When Fancy Eviction Fails |
| --- | --- |
| 决策层级 | 驱逐算法本身（跨 HBM 与内存池两种机制） |
| 使用的信号 | recency / frequency / quick demotion / compute-aware / capacity-adaptive granularity |
| 需要的外部信息 | 论文使用生产 trace 与自建模拟器，**无需先验工作流信息** |
| 适用场景 | 论文考察的生产前缀复用负载 |

### 8.3 原文结论（论文报告，非本项目结果）

简单 LRU 出乎意料地稳健，与复杂的传统策略表现相当（频率类算法往往更差）；同时距 Bélády 最优仍有可观的剩余空间。

### 8.4 对本项目的启发（这是本项目最重要的反向证据来源）

这篇论文**不能**只作为支持复杂驱逐算法的文献。它要求把四个方向都改成可检验的问题：

| 方向 | 该论文要求的研究姿态 |
| --- | --- |
| Block Idea 1 | 把"何时值得偏离 LRU"作为可检验问题，而非预设复杂策略更好 |
| Block Idea 2 | 验证中间信号相对 TTL/deadline proxy 的**增量**价值 |
| Entry Idea 3 | 检验复杂释放顺序相对简单规则的**实际改进**，而不是只证明规则之间存在差异 |
| Entry Idea 4 | 检验部分解除保护的收益是否足以抵消实现复杂度，以及其优势是否依赖容量、前缀共享结构与 miss cost 分布 |

**限制**：不得把该论文的实验结果当作本项目的实验结论，也不得仅根据标题推断其方法或结论。

## 10. 对后续工作的直接支撑

### 10.1 支撑 PPT（背景 / 相关工作 / 动机三章）

- **背景页**：vLLM Figure 1（KV 占用）+ SAGA "38% 重建开销"（注明条件：32 张 A100、vLLM v0.6.0、10 次重复）。
- **相关工作页**：第 9 节的横向对比表。
- **动机页**：Continuum Figure 4（传统引擎两类失败）→ *When Fancy Eviction Fails* 的反向证据 → 四个研究方向。
- **系统概览页**：模仿 vLLM Figure 4 / Continuum Figure 7 / ARC Figure 1 绘制。

### 10.2 支撑实验方案设计

- **指标体系**：命中率、TTFT（P50/P95）、吞吐、端到端延迟/完成时间；另记录驱逐次数、重算量与策略决策开销。证据分层按 `N`/`E`/`C`/`R`/`W`/`S` 报告（见 [`../专业术语表.md`](../专业术语表.md) §7）。
- **必报的诊断量**：候选方法间的 pairwise ordering agreement 与 rank correlation（Entry Idea 3），以及强制首释放窗口计数。
- **作图模板**：命中率 / TTFT vs. 缓存大小（ARC 图 3–5）；不同负载压力下的对比（ARC 图 6）。
- **公平性要求**：所有策略同一模型、同一 trace、同一缓存预算、同一运行时、同一种子。

### 10.3 明确不做的事（范围控制）

- 不复现 PagedAttention / vLLM 本身，不改注意力内核，不做多卡与分布式；
- 不复现 ARC、RLT/LBGR、SAGA、KVFlow、CacheWise 的完整系统；
- Continuum 风格基线复现其动态 TTL / retention 与程序级调度决策逻辑，不复现其完整系统，也不声称与论文逐行等价（[`../../baseline-freeze.md`](../../baseline-freeze.md)：只做 retention 不足以构成该基线）。
