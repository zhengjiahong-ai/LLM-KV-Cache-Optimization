# 对比笔记：相关工作横向对比（期末演示与报告用）

> **文档定位**：本文是 `论文总结.md` 的姊妹篇。`论文总结.md` 按"逐篇文献"纵向梳理，本文按"对比维度"横向展开。逐篇细节（核心机制、可复用图表）不在此重复，需要时查阅 `论文总结.md` 对应小节。
>
> **项目口径**（与 `docs/experiment-plan.md` 一致）：复现基线仅为 **vLLM 风格 LRU** 与 **Continuum 风格 TTL / retention policy**；本项目方法为 **在线动态成本感知驱逐策略**。

## 1. 对比的五个维度

所有横向对比统一采用以下五个维度：

| 维度 | 含义 | 为什么重要 |
| --- | --- | --- |
| **D1 作用层级** | 策略改的是内存布局、驱逐决策，还是调度/保留 | 界定相关工作与我们的工作是否在同一层面竞争 |
| **D2 决策信号** | 驱逐/保留决策依据哪些信息（时间戳、频率、成本、工作流图…） | 直接决定策略能否感知"异构成本" |
| **D3 决策时机与粒度** | 何时决策（到期/驱逐时刻）、对什么粒度决策（整会话/块/前缀） | 决定策略的灵活性与误杀风险 |
| **D4 信息需求** | 是否需要先验信息（工具统计、AEG 工作流图、编排器 hint） | 决定策略在真实黑盒场景下的可用性 |
| **D5 评估方式** | 用什么负载与指标验证 | 为我们选择实验指标与作图方式提供依据 |

## 3. 按主题类的成对对比

### 3.1 传统驱逐类：LRU vs. RLT

**共同点**：两者都在缓存压力下选择逐出对象，且不直接用候选块的重算时间排序。

| 对比项 | LRU | RLT |
| --- | --- | --- |
| 选择逻辑 | 按最后访问时间；在前缀树中可采用 Leaf-LRU | 未标记叶子 token 中随机一个 |
| 解决的问题 | 简单的访问历史基线 | 减弱对到达顺序的依赖 |
| 理论竞争比 | RLT 论文在其模型下给出 Leaf-LRU 最坏 \(O(n)\) | 同一模型下为 \(O(\log n)\) |
| 限制 | 不直接估计重算时间 | 随机选择不直接估计候选价值 |

**对我们的意义**：LRU 是我们的 Baseline 1；RLT 说明"比 LRU 好"不一定需要成本模型，因此我们的实验必须证明**收益来自成本信号本身**（消融实验的必要性，见 experiment-plan）。

### 3.2 自适应类：ARC

**与 LRU 的区别**：增加了频率维度与幽灵缓存反馈，能随负载调整新近度/频率的空间配比。

**与本项目方法的区别**（报告 Related Work 需写清）：

- ARC 调的是**两类队列的空间配比**，我们拟调的是**每个块的驱逐优先级**，两者的决策形式不同；
- ARC 的信号仍是"会不会再被访问"，不含"被逐出的代价有多大"；
- ARC 对系统状态（显存压力、排队）无反馈，其"自适应"只针对访问模式。

**可借用的实验方法**：命中率 / TTFT vs. 缓存大小的作图方式（ARC 图 3–5），以及 QuALITY/WikiQA/Zipf/多轮 trace 的负载组合思路。

### 3.3 保留租约类：Continuum vs. SAGA（重点，支撑 Baseline 2 的设计取舍）

两者都解决"Agent 工具调用挂起期缓存被误逐"的问题，都引入 TTL，但设计哲学不同：

| 对比项 | Continuum | SAGA |
| --- | --- | --- |
| TTL 计算依据 | 工具时长历史预测 + 程序轮次数 | 工具类型历史延迟分位数（如 95%） |
| 显存压力响应 | 空间不足时会选择部分已 pin 请求解除保护，防止死锁 | 有：压力因子缩短 TTL，高阈值下硬驱逐 |
| 到期后处理 | TTL 到期后解除 pin | TTL 不提供无限期保护，结合逐出管理 |
| 驱逐侧配套 | 无专门驱逐策略 | WA-LRU 驱逐分数（重用概率 + 新近度 + 大小 + TTL 状态） |
| 信息需求 | 工具调用历史（可在线收集） | AEG 或由历史 trace 推断的工作流 |
| 粒度 | 按请求的 KV 缓存 pin / unpin | 工作流任务及其缓存状态 |

**与本项目的主要差别**：

1. Continuum 的主要输出是 TTL；SAGA 除 TTL 外还提供基于 AEG 的逐出排序；
2. Continuum 的 TTL 计算考虑重算/重载和排队影响，SAGA 的 WA-LRU 不直接以候选块的重算时间排序；
3. 本项目拟在块级候选之间比较成本和复用信号。该差别是研究假设，不应预设为性能优势。

**对 Baseline 2 实现的直接指导**：

- 复现 Continuum 的 `CalcTTL` + pin/unpin + 优先级调度（指南见 `论文总结.md` §4.2）；
- 不将 SAGA 的 TTL 或 WA-LRU 机制并入 Continuum 基线；
- 基线不退化为普通 LRU（experiment-plan 的硬性要求）。

### 3.4 保留指令类：vLLM RFC #37003

来自 `参考文献/关于vLLM的参考文档与网址.md` 的第三份材料：社区提案允许编排器对 token 范围标注**驱逐优先级与生存时间**（retention directives），以解决 Agent 工作流下 LRU 误清会话前缀、引发高昂重算成本的问题。

- **定位**：工程提案而非论文，属于"自顶向下由调用方指定优先级"路线；
- **与我们的关系**：它提供由调用方声明保留优先级的接口；本项目拟根据运行时数据进行候选排序。两者可以互补，但 RFC 不应被当作已验证的性能证据。

## 4. 我们的方法与最接近工作的区分

### 4.1 与 SAGA 的 WA-LRU 对比

| 区分点 | WA-LRU | 本项目 |
| --- | --- | --- |
| 重用概率来源 | AEG，来源可为框架提示或 trace 推断 | 拟使用在线运行时复用历史 |
| 成本建模 | 不直接以候选块重算时间排序 | 拟显式估计重算成本 |
| 适用场景 | 需要 AEG 或相应推断模块 | 目标是只使用本地运行时数据 |

**一句话**：*"WA-LRU 使用 AEG 预测未来复用；我们拟在不接入 AEG 的条件下，用运行时历史估计复用和重算成本。"*

### 4.2 vs. Continuum —— 我们复现它，但不等于模仿它

| 区分点 | Continuum | 本项目 |
| --- | --- | --- |
| 回答的问题 | 挂起会话保留多久 | 显存不足时先逐出谁 |
| 决策对象 | 租约时长 τ | 驱逐候选排序 |
| 全局状态 | 空间不足时可解除部分 pin | 拟将缓存压力纳入成本函数 |

两者正交：理论上我们的成本感知驱逐可以与 TTL 保留叠加使用，可尝试**组合**。

### 4.3 与 RLT 的区别

*"RLT 不加成本信息也能改善 LRU，成本模型是否必要？"*

回答：

- RLT 的结论来自特定前缀共享和到达顺序模型，不能直接推出其他负载中的表现；
- 本项目通过消融实验比较仅重算成本、仅复用信号和完整模型，以检验成本信号是否带来额外收益。
