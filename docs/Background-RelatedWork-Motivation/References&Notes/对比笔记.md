| 工作 | 研究问题与服务环境 | 负载与评估条件 |

| PagedAttention / vLLM | 动态 KV 分配、碎片和共享 | OPT 系列，ShareGPT/Alpaca，连续分配系统对照 |

## 3. 可借鉴的比较与边界

| 工作 | 可借鉴 | 不能从论文比较推导的项目结论 |
| --- | --- | --- |
| PagedAttention / APC | 解释为什么可按物理 Block 管理和共享 | 序列抢占和恢复策略等同于当前 GPU APC 驱逐 |
| ARC / RLT / LBGR | 访问历史和简单策略的比较价值，替换与路由应拆开 | 命中率、竞争比或多 worker 时延可直接换算为 Native 重算 token |
| Continuum / SAGA | 比较程序生命周期、TTL、压力释放和调度怎样分工 | A0 复现原系统，或 A0−N0 衡量完整系统的时延差 |
| KVFlow / CacheWise | 对照工作流距离和工具元数据两类复用信号 | 预取或准入带来的增益归属于本项目 Block selector |
| WFEF | 保留强 recency 对照，按容量检验增量价值 | LRU 普遍最优，或 partial-node eviction 等价于 partial-tail Entry unpinning |

### 项目内怎样做公平比较

在同一 Workload Group 和 C1/C2 条件内保持输入、容量、压力路径及 Native scheduler 一致。A1/A3 对 A0 比较 Entry Release，A2 对 A0 比较 Physical Block Victim Selection，A0 对 N0 检查 forced Entry Release，A3 对 E0 检查后缀成本模型相对 deadline-only Step 2 的决策可判别性。E0 的分支与回退约束按冻结协议解释。各论文的系统级结果可支持机制讨论，项目的效应估计按独立 N/E/C 证据与 Workload Group 分析。见 [Protocol v4](../../phase3-final-evaluation-protocol-v4.md)和[机制覆盖及结论边界](../../experiments/phase3-mechanism-coverage-and-claim-boundaries.md)。
