# 项目动机：面向 Continuum 风格 KV Cache 管理的成本感知优化

本页说明研究背景、两层决策及评估动机。正式研究问题、贡献和执行状态分别见[研究定位](../research-motivation-and-contributions.md)与 [M1 状态账本](../research-status.md)。

## 1. KV Cache、容量压力与多轮复用

自回归推理将历史 token 的 Key/Value 张量保存在 KV Cache 中，后续生成可重用这些状态。PagedAttention 让系统按物理 Block 分配，GPU APC 进一步复用跨请求的相同前缀。GPU 容量有限时，留住一个暂时空闲的前缀会挤占其他请求的分配空间。若该前缀被回收且稍后无法命中，系统需要重新执行相应的 prefill。该代价取决于是否再次复用、可用的连续前缀以及模型和上下文条件。见[论文总结 §1、§8](References&Notes/论文总结.md)。

Native LRU 是必要的 Block 层对照。它利用最近访问顺序，无需额外的工作流信息。在活跃会话持续复用前缀时，recency 往往已有较强预测力。WFEF 在其生产 trace 和容量扫描中同时观察到复杂策略收益有限以及小容量下替代策略胜出的情形。项目因此把成本信号的增量价值作为待检验问题。见[相关工作总结](相关工作总结.md)。

## 2. Continuum-style adaptation 提供系统基础

多轮 Agent 的一次 program 会跨越多个 Native 请求。模型等待工具时，该前缀短期没有访问，但后续轮次可能接着使用。只看最近一次 Native 请求的访问时间，难以表达这个等待窗口。Continuum 用 program identity 和工具间隔历史估计保留时长，并协调 program 返回后的调度。

Phase 1A 验证了项目的 Block-level EvictionPolicyAdapter 与 Native 路径。Phase 1B 进一步适配显式 program/session identity、服务端请求间隔、Dynamic TTL、软保护与惰性过期、确定性压力释放和窄范围 admission-order adapter，并在合格的 Metal profile 上完成真实运行时验证。该适配保留 vLLM 0.27.1 对 BlockPool、引用计数、APC hash、分配和清理的所有权。验证范围是项目侧集成，论文源码、原始负载和完整系统的等价性不在该证据范围内。见[适配器设计](../policy-adapter-design.md)、[基线冻结](../baseline-freeze.md)和 [Phase 1B final report](../experiments/phase1b-continuum/final-report.md)。

## 3. 容量不足时的两个决策

| 决策 | 问题 | 直接作用 |
| --- | --- | --- |
| 逻辑 Entry Release | 普通候选不足时，先解除哪个受保护 Entry？ | 清除该条目的保护，改变其关联 Block 的 eviction eligibility |
| Physical Block Victim Selection | 在合法物理候选中，选择哪些 Block？ | 将 victim 交给 Native vLLM 实际驱逐与清理 |

Phase 3 的 A0 是项目侧 Continuum-style Entry Release 基线。其压力释放顺序不是只有 deadline-first，而是按 `(Entry deadline, newly eligible Blocks 的 minimum Native LRU rank, deterministic Entry identity)` 排序；第二键取仅因释放该 Entry 而新获得资格的 Block 中最小 Native LRU rank，若没有新增资格 Block 则按正无穷处理。该排序键决定先释放哪个 Entry，不改变后续物理 victim selection：A0 仍使用 Native LRU。此规则是项目冻结适配，不是 Continuum 论文按 latest program arrival time 的死锁预防规则。

一个 Block 可以关联多个逻辑前缀。解除某个 Entry 的保护后，Block 若仍有活跃引用或受另一 Entry 保护，仍不可被选中。即使某些 Block 新增资格，下游也可能选出同一组 victim。实际驱逐后，只有当后续请求需要相应前缀且该内容未能通过 APC 复用时，才可能增加重算。释放顺序、实际 Native hashed eviction、后续 APC hit/miss 和请求级重算需要分别取证。见[专业术语表](专业术语表.md)和[机制覆盖及结论边界](../experiments/phase3-mechanism-coverage-and-claim-boundaries.md)。

## 5. 当前评估为什么需要独立证据

跨臂应绑定相同请求、token 输入、容量、压力路径和运行条件。可比的候选构造不要求各策略输出相同 eligibility 或 victim，因为这些正是要观测的变化。Block ID 可被复用，内容身份需要 Native hash 及请求证据。一次 hashed eviction 与后续 miss 的时间关联仍有归因边界。

请求级指标分别建立 N（Native prompt tokens）、E（按冻结规则可复用的前缀 tokens）和 C（实际 Native APC 命中 tokens）。同一 cell 逐请求的 E 跨臂一致，且满足 0 ≤ C ≤ E ≤ N。Σ(E−C) 计量可复用前缀的重算，N−C 包含真正新增的后缀 N−E。缺失或冲突证据应按协议保留并处理。推断单位是 Workload Group，C1/C2、turn、request 和 repeat 不增加独立 Group 数。见 [Protocol v4](../phase3-final-evaluation-protocol-v4.md)和[独立 N/E/C Evaluator](../experiments/phase3-engineering-preparation-stage2.md)。

## 6. Phase 3 的比较范围

- **N0 / A0** 保持压力请求、Native scheduler 与 Native LRU/APC 的共同路径，用于比较是否执行冻结的 forced Entry Release。
- **A1 / A3 / E0** 在 Entry Release 层采用冻结规则，物理层仍使用 Native LRU。A1/A3 对 A0 比较 Entry 策略，A3 对 E0 检查后缀成本排序相对 deadline-only Step 2 的可判别性。
- **A2** 保留 A0 Entry Release，在合法候选中用 Cost-Aware selector 替换 Native LRU。

六臂均使用 Native scheduler。协议没有 Static TTL 臂，因而不估计 Dynamic TTL 相对 Static TTL 的效应，也不估计 Phase 1B scheduler adapter 的因果贡献。A0−N0 的解释限于 forced Entry Release 的增量效应，不能代表原始 Continuum 与 Vanilla vLLM 的全系统比较。

Protocol v4 复用已有的 40 次 A0 Load Calibration。270 个新 runs 包括 30 次 A0 Noise Calibration，以及通过机器校验的转换门槛后执行的 240 次 Main Campaign。执行状态以[M1 状态账本](../research-status.md)为准，结论按[冻结协议](../phase3-final-evaluation-protocol-v4.md)和[执行授权](../experiments/phase3-option-f-270-run-pipeline-authorization.md)解释。

## 7. 潜在未来研究方向

证据感知的 Block 策略介入、工作流运行时信号驱动的 Block 选择、下游成本感知的 Entry Release 和 partial-tail Entry unpinning 均为研究储备。已有机制的局部重叠、实施边界与验证前提见[潜在未来研究方向](../future-research-directions.md)。四项均不属于 Phase 3 已授权的实验工作。
