## 1. PagedAttention / vLLM —— 一切研究的底座

> 文献：*Efficient Memory Management for Large Language Model Serving with PagedAttention*

### 1.1 核心机制/算法

- **问题量化**：传统系统把 KV 缓存放在连续内存中，产生严重的内部碎片（预分配过大）与外部碎片，实测 KV 缓存内存利用率低至 **20.4%**，直接限制了批大小与吞吐。
- **PagedAttention**：借鉴操作系统虚拟内存分页，把 KV 缓存切成固定大小的块，允许非连续存放、按需动态增长，几乎消除碎片；块级管理天然支持跨序列共享（并行采样、Beam Search、共享前缀），配合写时复制（Copy-on-Write）进一步省内存。
- **驱逐与恢复**：由于自回归推理要求一个序列的所有 KV 块同时在场，vLLM 采用 **"全有或全无"** 的驱逐策略；恢复时提供 **交换到 CPU 内存** 与 **重计算** 两种方案。

### 1.2 基线复现价值

- **不需要复现**该论文本身。它是我们所有实验的运行载体（最终后端基于 vLLM）。
- 需要继承的设定是块级（固定大小块）的缓存管理粒度。**Baseline 1** 采用实验计划中定义的 vLLM 风格 LRU，不将其表述为 PagedAttention 论文的默认逐出实现。

### 1.3 对本项目的启发

- **正面**：分页使"以块为单位做驱逐决策"成为可能，我们的成本评估函数天然作用在块/前缀粒度上。
- **局限**：该论文讨论的"全有或全无"恢复方式以序列为单位，未给出按候选块重算损失排序的策略。项目若改为块级排序，需要在实现中确认不破坏后端的块表和引用计数约束。
- **参考**：交换 vs. 重计算的权衡分析，可直接用作我们定义"重算成本"信号时的依据。

## 2. Recency-Frequency Adaptive KV Caching（ARC）—— 自适应但仍"成本盲目"

> 文献：*Recency-Frequency Adaptive KV Caching for LLM Serving*

### 2.1 核心机制/算法

- **动机**：LRU 只看新近度，无法应对多样化负载；不相关的工作负载会互相冲刷缓存。
- **机制**：把操作系统中的 **自适应替换缓存（ARC）** 引入 vLLM：
  - **双队列**：低频队列（L1，只访问过一次）与高频队列（L2，访问多次），L1 中被再次命中的项晋升到 L2；
  - **幽灵缓存（Ghost Cache）**：只记录被逐出块的元数据，用于估计"如果缓存更大能否命中"，其命中情况作为反馈信号，动态调整 L1/L2 的物理空间配比。

### 2.2 基线复现价值

- **不复现为基线**。它的价值是作为 Related Work 中的"中间档位"：比 LRU 聪明（多了频率维度和自适应），但离我们的目标仍差一步。
- 其实验设置可作为参考：对比纯 LRU，使用 QuALITY、WikiQA、合成 Zipf 负载和多轮对话 trace，并报告命中率与 TTFT。最终数据集和指标仍以 `docs/experiment-plan.md` 为准。

### 2.3 对本项目的启发

- **可借鉴**：
  - 频率是一个独立于新近度的有效复用信号，我们的成本函数可以把"近期复用历史"纳入；
  - 评估函数不应是静态的，应随负载动态调整——呼应我们"在线动态感知"的定位；
  - 幽灵缓存提示我们：即使一个块当前不活跃，也可以低成本地保留它的元数据来估计潜在收益。
- **局限（即我们的突破口）**：
  - **不感知重算成本**：ARC 只关心"会不会再被访问"，不关心"被逐出后再访问要花多大代价"；
  - **不感知异构代价**：不同长度、不同位置的块被一视同仁；
  - **自适应范围有限**：它调的是新近度/频率的配比，而不是对实时系统状态（显存压力、排队）的响应；
  - 实验中 KV 块固定为 16 token，未考虑不同内存足迹下的价值最大化。

## 3. Randomization-Boosts-KV-Caching（RLT + LBGR）：理论参照

> 文献：*Randomization Boosts KV Caching: Learning Balances Query Load — A Joint Perspective*

### 3.1 核心机制/算法

- **对 LRU 的批判（可直接引用为动机素材）**：
  - 对动态在线查询脆弱，容易逐出后续就要用的 KV，导致未命中与延迟上升；
  - 多 LLM 场景下，缓存亲和与全局负载均衡目标冲突，LRU 表现不稳；
  - **理论上**：前缀共享结构下 LRU 最坏情况竞争比退化为 \(O(n)\)。
- **RLT（Randomized Leaf Token eviction）**：缓存满时，从**未标记的叶子 token 中随机选一个逐出**。随机性打破了对查询到达顺序的依赖，最坏竞争比改善到 \(O(\log n)\)。
- **LBGR（学习型贪心路由）**：用在线学习估计端到端延迟（服务时间 + 队列负载 + 残差校正）来路由请求。

### 3.2 基线复现价值

- **不复现为基线**（超出课程项目范围）。它说明在论文给定的前缀共享和到达顺序条件下，随机化也能改善 LRU；实验讨论中应说明本项目与其比较的是决策信号，而非直接比较性能。
- **指标体系直接复用**：命中率、吞吐、延迟与 TTFT 均报告 **P50 / P95**，并给出驱逐与路由的**运行时开销分解**——这正是我们实验计划中"优化开销"一节的范本。

### 3.3 对本项目的启发

- **可借鉴**：
  - "在随机/简单选择之前先排除高价值项"的思路，天然契合我们的成本排序；
  - LBGR 的延迟估计公式（服务时间 + 队列负载 + 残差校正）启发我们：驱逐成本函数也可以是**多维信号的在线估计**，而非固定公式；
  - 竞争比分析为我们评价自己的策略提供了理论工具（至少可以引用）。
- **局限（即我们的突破口）**：
  - RLT 的逐出决策是**随机的**，完全不评估单个块的"价值"或"重算代价"；
  - 成本估计只发生在**路由**环节（对整个查询），而不是**驱逐**环节（对单个块）；
  - 未利用共享度、访问频率等更细的复用信号；内存足迹也不在决策内；
  - 其成本模型聚焦时间维度，没有刻画异构的重算成本（如长前缀重算对 TTFT 的破坏）。

## 4. Continuum —— 必须复现的强基线（TTL / retention policy）

> 文献：*Continuum: Efficient and Robust Multi-Turn LLM Agent Scheduling with KV Cache Time-to-Live*

### 4.1 核心机制/算法

- **问题**：Agent 工作流中工具调用会让 LLM 请求暂停。传统管理下，暂停期间 KV 缓存可能被驱逐（返回后要重新做昂贵的预填充），同时 GPU 资源被其他请求占用（返回后还要再排队，即"调度气泡"）。
- **核心思想**：**工具感知的 TTL + 程序级调度**。
  - 请求完成但程序未结束时，把其 KV 缓存 **pin（固定）** 在 GPU 内存；
  - 为每个 pin 设置 **TTL 过期时间**，防止无限占用；
  - 调度器按「抢占请求 > 已 pin 的请求 > 程序级 FCFS」定优先级。
- **TTL 计算依据**：工具调用时长的历史记录，以及论文中的缓存占用、重算/重载和排队影响估计。
- **关键机制细节**：TTL 到期且下一请求未到达则释放；内存不足时选择性解 pin 防死锁。

### 4.2 基线复现价值（重点：这是我们的 Baseline 2）

复现范围聚焦其**决策逻辑**，而非整套系统。核心要素：

- **核心算法**：
  1. `CalcTTL` 函数：基于工具调用时长统计与程序轮次计算过期时间；
  2. pin / unpin 逻辑：按 `CalcTTL` 结果保留或释放 KV 缓存；
  3. 调度优先级：已 pin 请求优先 + 程序级 FCFS；
  4. 死锁预防：内存压力下选择性解 pin。
- **核心数据结构**：
  - `Pinned_Programs_Map`：`program_id → TTL_timestamp`；
  - `Historical_Tool_Call_Records`：`(tool_type, interval_time)` 在线统计；
  - `Global_Stats` / `Per_Tool_Stats`：工具时长的均值与标准差。
- **实现注意事项**：正确识别程序 ID 与工具类型、精确测量工具调用间隔、实现 pin/unpin 机制、改调度优先级、防死锁。
- **边界提醒**（与 experiment-plan 一致）：复现范围冻结前需书面记录——复现了哪个决策机制、与原始系统有哪些运行时假设差异、省略了哪些组件、为何比较仍然公平。该基线**不得退化成普通 LRU**。

### 4.3 对本项目的启发

- **可借鉴**：
  - "保留决策需要量化收益"的思想：pin 的收益 = 省下的重算 + 省下的排队，代价 = 占用的显存时间；
  - 在线收集工具调用统计并更新预测——一种轻量的"在线感知"范式；
  - 其局限恰好指出我们的改进方向（见下）。
- **与本项目的差别**：
  1. Continuum 会在空间不足时解除部分 pin 以避免死锁，但其主要输出仍是每个请求的 TTL，而非对全部可逐出块的统一排序；
  2. TTL 依赖工具调用历史。冷启动、工具时长变化或长尾都会影响估计质量；
  3. 论文的保留和解除保护以请求的 KV 缓存为单位，不区分同一请求内不同块的重算价值；
  4. 本项目在容量不足时排序候选块。该决策点可与 TTL 保留组合。

## 5. SAGA：工作流感知的保留与逐出参照

> 文献：*SAGA: Workflow-Atomic Scheduling for AI Agent Inference on GPU Clusters*

### 5.1 核心机制/算法

- **问题**：传统调度器将每次 LLM 调用视为独立请求。论文在 SWE-bench 上报告，vLLM v0.6.0 有 **38% 的执行时间用于在 Agent 步骤间重建 KV Cache**。文中所述 Agent 任务的 KV Cache 规模为 2–12 GB。
- **工具调用感知 TTL**：
  - 基础 TTL 来自特定工具类型的历史延迟（如取 **95% 分位数**）；
  - **显存压力大时按比例缩短 TTL**；设最大上限（如 300 秒）；
  - 内存压力达到高阈值时会触发硬驱逐，TTL 不是无限期保护。
- **WA-LRU（Workflow-Aware LRU）**：使用 AEG 预测的未来复用概率、新近度和缓存大小进行逐出排序。
- **AEG 来源**：论文可使用编排框架提供的提示，也可由历史请求 trace 进行模式推断。

### 5.2 基线复现价值

- **不复现为基线**。其价值有两点：
  1. 作为 Continuum 基线的对照设计参考，帮助说明保留时长、内存压力和驱逐排序可以分开设计；
  2. WA-LRU 是最接近本项目的相关工作之一。两者的主要区别是，SAGA 使用 AEG 预测复用，而本项目拟只维护本地运行时历史，并额外估计重算成本。

### 5.3 对本项目的启发

- **可借鉴**：
  - **显存压力动态缩放 TTL** 的思路，可作为我们成本函数中"当前缓存压力"信号的参照实现；
  - "未来复用概率 + 缓存属性"可形成排序分数，这为设计多信号策略提供了参考；
  - 评估指标 **TCT（任务完成时间）、GPU 内存利用率、驱逐竞争比（对照 Bélády 最优）** 值得纳入我们的指标讨论。
- **与本项目的差别**：
  - SAGA 需要 AEG 或相应的 trace 推断，接入和预测误差都是额外条件；
  - WA-LRU 的分数不直接以候选块的重算时间为输入；
  - 本项目拟用本地运行时历史估计复用，并将重算成本纳入候选排序。该定位需要通过实验验证，而非预设性能结论。

- **指标体系**：命中率、TTFT（P50/P95）、吞吐、端到端延迟/完成时间（对齐 ARC 与 RLT 论文的报告方式），另记录驱逐次数、重算量与策略决策开销（对齐 experiment-plan 的 Metrics 一节）。
- **作图模板**：命中率 / TTFT vs. 缓存大小（ARC 图 3–5）；不同负载压力下的对比（ARC 图 6）。
- **负载选择参考**：长文档 QA 类（QuALITY/WikiQA 思路）、合成 Zipf 分布负载、真实多轮对话 trace、Agent 类负载（SWE-Bench / BFCL 思路）——最终以 Member 5 冻结的数据集方案为准。
- **公平性要求**：所有策略同一模型、同一 trace、同一缓存预算、同一运行时、同一种子（与 experiment-plan 的 Experimental Comparisons 一致）。

### 7.3 明确不做的事（范围控制）

- 不复现 PagedAttention / vLLM 本身，不改注意力内核，不做多卡与分布式；
- 不复现 ARC、RLT/LBGR、SAGA 的完整系统；
- Continuum 基线只复现其 TTL / retention 决策逻辑。
